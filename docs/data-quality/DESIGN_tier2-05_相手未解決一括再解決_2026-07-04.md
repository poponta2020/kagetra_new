## 2. 設計

### 2-a. バッチ再解決ドライバ（scratch・`scripts/diagnostics/_t5reresolve.mts` 想定）

- 対象: `status='normal' AND opponent_participant_id IS NULL AND opponent_name IS NOT NULL`。**t1459 は大会ごと除外**（名のみ記録・同姓多数で別人リスク。#18の再取込課題に送る）。
- 大会単位で全級 participants をロードし、`normalizePlayerName`（JS実装をimport・アプリと完全同一）でインデックス構築。
- 階層判定は **T1→T2→T3→T4 の確度順・先勝ち**。T3 は norm長≥2 のみ。T5_short は触らない。
- **結線前の安全ゲート（全tier共通）**:
  1. 非NULLの opponent_participant_id は絶対に上書きしない（NULL埋めのみ）
  2. 結線により**新たな勝敗矛盾を作らない**: 候補相手の同round行が存在し result が同方向なら結線しない（skip・理由記録）
  3. 結線により**同round重複の解釈を壊さない**: 候補相手の同round行が複数あるなら結線しない
  4. 往復照合: 候補相手の同round行がこちらを（id or 正規化名で）指していれば強確証。**相手側行が存在しない場合（ミラー欠落級）は T1/T2/T4 は結線可・T3も結線可とするが、確証レベルを提案CSVに記録**（ミラー行の機械生成はしない=既定方針どおり）
  5. sd非対称は許容（原本忠実・記録のみ）
- 二次回収（T1amb/T3amb/T4amb 1,348件）: 往復照合（同round・逆result・同枚数・相手側がこちら名を指す）で**一意に絞れた場合のみ**同バッチで結線。絞れなければ null 維持（現状どおり曖昧の明示）。
- **DRY_RUN**: tournament×class×tier 別の提案CSV（match_id / opponent_name / 解決先 participant_id・氏名 / tier / 往復照合結果）を出力 → tier別無作為サンプル（特にT3から30件）を原本と人手突合してから適用へ。
- **適用**: UPDATE のみ（削除・INSERT なし）なので全体を**単一tx**＋件数アサーション（更新件数=提案件数・適用後 opp_null_normal=理論値・矛盾ペア増0・同round重複増0）。適用直前に対象 matches 行を COPY 退避。**リハ(5433)先行 → read-back → 本番**、台帳記録。
