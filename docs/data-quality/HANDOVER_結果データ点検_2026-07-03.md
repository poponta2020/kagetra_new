## 4. Tier 2 で本番を修正するときの手順（合意済み運用）

1. **リハDB `kagetra_rehearsal`（ローカル5433）で検証してから本番へ**（大会単位の再取込・削除など大きい操作）。行レベルの小修正は本番直接でよいが、いずれも:
2. 対象行バックアップ → 単一トランザクション → read-back（件数・内容照合）
3. **1件ずつ「原本vsDBのdiff提示 → ユーザー承認 → 適用」**。承認なしのバッチ適用禁止
4. 修正のたびに台帳へ記録（台帳ファイルは Tier 2 開始時に `docs/data-quality/result-fix-ledger.md` として新設予定）＋claude-mem 記録
5. 削除・再取込後は派生の再計算を忘れない: display_name（recomputePlayerDisplayNames）/ dan_rank / derived_bracket / num_players。全体整合監査はセッション末尾に一括
6. **禁止事項**: 本番 db:push（series層は Drizzle 非定義）／明示GOなしの本番書込／スキーマ変更

## 7. 落とし穴・注意

- **重複判定を機械的に横展開しない**: 年2回開催・2日制（高松宮C 1日目/2日目=参加者重複0%で正当）・E級ブロック分割は正当な構造。判定は「参加者重複率≥90%＋同一対戦実在」の2段で
- edition の year は**シーズン年**（1〜5月開催は前年に付く）。マトリクスも edition year 基準
- tournaments の identity は「名前＋開催日」。まとめ報告ファイルは日付が違うため dedup をすり抜ける（今回の二重取込の根本原因）。**今後の取込でも再発しうる**ので、取込時に edition 内の同 grade 参加者重複チェックを入れるのが恒久対策候補
- 日付なし大会101件は年ソートで末尾に落ちる（アプリ表示で気づかれやすい）。ミュンヘン(t1443)以外は edition 経由で年が判明しているので、`event_date` の補完は Tier 2 の低優先候補
- 検査時の相手未解決カウントは status=normal のみ（walkover/forfeit の相手なしは正当）
