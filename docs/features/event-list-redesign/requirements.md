# event-list-redesign 要件定義書（改修モード）

> **対象**: `/events` 大会申込一覧（`apps/web/src/app/(app)/events/`）。
> 現行仕様の正典は [`../event-list-refinements/requirements.md`](../event-list-refinements/requirements.md)（PR #251 で実装済み）。本書はそこからの **delta（変更差分）** であり、変更対象外の現行挙動はすべて維持する。
> **見た目の正**は [`design-spec.md`](./design-spec.md)（locked）＋ `design-mock/redesign.html`。本書ではレイアウトを言葉で再記述しない。

## 1. 概要

- **目的**: 一覧を「自分が出られる大会を締切順に流し見できる」画面にする。
- **背景**: 本番実測（2026-07-26）で、15行中6行が「締切済」として先頭を占有し、全行「参加 0名」の同値ノイズが下段を埋めていた。デザイン往復（Claude Design・Round 1〜4）で方向性を確定済み。

## 2. 変更内容（before → after）

### 2.1 締切済の大会を一覧から除外する ★ロジック変更
- **before**: 会内締切（internalDeadline）超過の大会も「締切済」表示で残る。締切日順（既定）では先頭に固まる。
- **after**: `internalDeadline < 今日(JST)` の大会は一覧に**表示しない**。ただし例外:
  - **自分が出欠回答済み（attend=true）の大会は表示を継続**する（「申し込んだか」の確認導線を維持。表示は現状どおり「締切済」淡色、帯は砂＝新規申込不可のため）
  - 締切**当日**（daysLeft=0）は表示する（「本日」強調）
  - 締切**未設定**（null）は現状どおり表示する（「締切 —」・締切日順では末尾）
- 除外はサーバー側の母集団条件ではなく**表示フィルタ**として行う（自分の attend 状態でユーザーごとに行集合が変わるため）。
- **残った「自分の締切済」行の並び**: ソートは現行ルールのまま（締切日順なら締切が最も早い＝リスト最上部に来る）。自分が申し込んだ大会であり確認対象なので、最上部でよい（沈める処理は入れない）。
- **見え方**: 締切＝「締切済」淡色／帯＝砂／meta 行は AC-5 の規則どおり描画（自分が attend=true なので必ず 1 名以上＝自分の苗字を含む）。この状態はモックに描かれていないため design-spec §Round 5 の記述が正。

### 2.2 参加者表示の刷新 ★ロジック変更
- **before**: 「参加 N名」＋苗字チップ最大5個＋「他N名」。0名でも「参加 0名」を表示。
- **after**: 参加者 0名の行は**下段（meta 行）ごと非表示**。1名以上の行のみ、人数（藍・大きめ）＋苗字を「・」区切りテキストで**全員表示**（上限・「他N名」廃止。折り返し可・苗字の途中では切らない）。
- サーバーの苗字取得上限（`slice(0, CHIP_LIMIT)`）も撤廃し全員分を渡す。並びは現状どおり**級昇順（未設定は末尾）**。

### 2.3 参加可否の色帯（新規・表示のみ）
- 各行の左端に 3px の縦帯: **藍＝canApply true（自分の級が対象）／砂＝false**。
- canApply の判定ロジック（級のみ・`isGradeEligible`）は**不変**。新データ不要。
- **中止イベントの帯は砂固定**（級が合っていても申し込めないため）。

### 2.4 純粋な見た目変更（ロジック不変・詳細は design-spec）
- 上段の並びを「大会名 → 日付 → 締切」に入替え（現状は日付先頭）。日付は 13.5px・淡い墨に従属化。
- 締切カウントダウン: 数字のみ拡大（通常15px／3日以内19px・色は墨のまま）。**当日のみ朱の塗りピル**（現状の soon=墨太字・today=朱文字から変更。朱の用途を当日に限定）。
- ページ余白 16px を導入（現状はゼロ＝画面端ベタ付き）。**適用先は /events のページコンポーネント内**に限る（`mobile-shell.tsx` の `<main>` には入れない — /tournaments・/players/[id] 等は各ページが自前で `p-4` を持つため、共通シェルに入れると二重に余白が付く）。

## 3. 変わらないもの（回帰境界）

- ソート2軸（開催日順/締切日順・既定=締切日順・昇順・null末尾）と「申込可能のみ」スイッチの挙動
- 母集団: 未来イベント（eventDate >= 今日）・`not_applying` 除外・/events-archive との棲み分け
- 行タップで `/events/[id]` 遷移／中止ピル（danger）＋タイトル淡色／全体0件・フィルタ0件の空表示文言
- 見出し「大会申込」・「過去のイベント →」・管理者のみ「新規作成」
- canApply 判定（級のみ・管理者バイパスなし）／締切 tone のしきい値（SOON_THRESHOLD=3）／todayStr 方式（hydration 対策）
- AppBar・ボトムナビ・他画面（詳細/archive/ダッシュボード）

## 5. Non-goals

- /events-archive・イベント詳細・ダッシュボードの変更（締切後の確認導線は AC-2 の表示継続で担保し、他画面に代替導線を作らない）
- ボトムナビ・AppBar の変更
- canApply 判定の拡張（締切・中止を判定に含める等）／締切しきい値の変更
- 「申込可能のみ」フィルタと帯の連動仕様の変更（フィルタは従来どおり canApply で絞る）
- 他ページへのページ余白 16px の展開（本画面のみ。全体統一は別スコープ）

## 6. 技術的制約・契約

- 表示フィルタ・並び替えは既存の純関数群（`event-list-utils.ts`）の拡張で行い、`Date.now()` を使わず `todayStr` を渡す現行方式を維持する
- 「自分が attend=true か」の判定データ追加で一覧クエリの N+1 を作らない（既存の participantRows 1クエリの範囲で解決する）
- EventListItem のシリアライズ境界（Server → Client）を維持。個人情報は苗字（surname）のみクライアントへ渡す（現行どおり）
- Tailwind v4 トークン準拠（design-spec の忠実度チェックリストが照合先）。朱の使用は「当日」塗りピルのみ
- **`mobile-shell.tsx` を変更しない**（余白は /events ページ側で完結。共通シェルに余白を足すと自前 `p-4` を持つ既存ページが二重余白になる）

## 7. 設計判断の根拠

- **締切済の非表示＋自分申込済みは残す**: 申し込めない行が一等地を占める問題と、「申し込んだかの確認」導線消失リスクの両立（2026-07-26 ユーザー決定）
- **帯=藍**: Round 2 の朱案はブランド規約（参加=藍/朱=否定・警告）と逆転するため規約準拠へ（ユーザー決定）
- **朱を当日限定に**: Round 4 のユーザー編集。緊急シグナルの希釈を防ぐ
- **チップ廃止・全員表示**: チップは面積が出て大会名より目立つ／「他N名」は結局誰か分からない（Claude Design 検討・participants-options 比較の帰結）
