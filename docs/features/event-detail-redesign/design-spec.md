# 大会申込詳細リデザイン デザイン仕様（design-spec）

> `/design-screen` が出力する確定仕様。実装は `/define-feature event-detail-redesign` で要件化してから行う（**純UIではない** — 新ロジック・機能削除を含むため）。
> **レイアウトの詳細は視覚の正（`design-mock/redesign.html`）が正。** このファイルはそこから読み取れない意図・判断・データ要件・宿題と、忠実度チェックリストを記述する。

## 1. 対象と狙い

- **対象画面:** `/events/[id]`（`apps/web/src/app/(app)/events/[id]/page.tsx` と関連コンポーネント）。管理者ビュー・一般会員ビューの両方
- **現状の不満:** 管理者ビューが 13 ブロックの縦積みで極端に長い。「会員が読む情報」（詳細・出欠・名簿）と「運営操作」（進行管理・LINE・取込・関連メール）が交互に混ざり、参加ボタンに届くまでのスクロールが長い。カードの入れ子で情報が箱に埋もれる。日付が生 ISO 表記（`2026-09-06`）
- **狙い:** この画面のアンカーを「9/6(日) 広島CDE」のタイトル1つに定め、読む情報を箱から出す。運営操作は畳んで、既定表示では会員も管理者も「どの大会か・今どの段階か・自分は出るか」だけが見える状態にする
- **主ユーザー / 主な使い方:** 会員＝出るかどうかを決める・名簿で自分の掲載を確認する。管理者＝会としての申込/支払の進行を管理し、LINE 配信の状態を見る

## 2. 採用した方向性

- **方向性:** **罫線＋余白主導（脱カード）** — カードを原則全廃し、下線付き見出し＋余白（34px）＋ヘアライン罫線で構造を作る。箱を残したのは**関連メール1件**のみ（＝タップして開く独立した物体）。`docs/design/design.md` 2.5「アンチスロップ規約」の「読む情報を箱に入れてはいけない」に準拠
- **不採用案と理由:** 現状のカード積層（`current.html`）— カードを1枚はがしても情報は読めるため、箱が構造を作っていなかった（2.5 のリトマス試験に不合格）。長さの主因でもあった
- **視覚の正:** `design-mock/redesign.html`
  - カード: Claude Design「Kagetra Design System」→ グループ **大会申込 詳細リデザイン** → `features/event-detail-redesign/redesign.html`
  - 比較用の現状再現: 同グループ `current.html`（ローカルは `design-mock/current.html`）
- **最終確認時の状態:** `redesign.html` 内に、左=管理者ビュー（申込済/未払・LINE 配信中）、右=一般会員ビュー（山田さん・D級・未回答）、下部に「状態バリエーション」5断片

## 3. 視覚の正に現れない設計判断

- **sticky ヘッダーは1つのラッパーで固定する。** 日付+大会名・会場・申込フローの3要素を個別に sticky にするとオフセット計算が壊れやすいため、`.stickyhead` 1枚にまとめている。ここを分割すると崩れる
- **既定はすべて閉。** 進行管理・LINE 配信・名簿・関連メールを `<details>` で畳むことが「会員ビューがほぼ1画面」を成立させている。既定を開にすると狙いが消える
- **申込フローは両ビュー共通の「会としての進行」を表す。** `events.entryStatus` / `paymentStatus` は会単位の状態なので、会員にも同じマイルストーンを見せる（会員個人の出欠は最下部の参加ボタンが担う）
- **ステップは欠かさない。** 抽選日・支払締切などが NULL でもステップを消さず、日付欄に「未定」と出す（ユーザー指定）。ステップ数が大会ごとに変わると、フローが横並びの目安として機能しなくなるため
- **関連メールだけ箱を残したのは、逆説的に「ここがタップできる」を伝えるため。** 画面唯一の箱であることが意味を持つので、他所に箱を足すと効果が消える
- **名簿を級の若い順に並べ替える。** 現状は取込順。級タブ（全体/C/D/E）と併せて「自分の級を探す」動線に最適化する

## 9. ガードレール準拠メモ

- **配色:** ブランド規約（参加=藍 / 警告・否定=朱）に完全準拠。`event-list-redesign` Round 2 で起きた「朱＝参加できる」の意味逆転はこの案には無い
- **トークン逸脱:** トークン外の**色は 0 件**（`rgba(244,239,227,.95)` は `--kg-bg` の 95%＝現行 sticky と同値）。**サイズは 2 件が型スケール外** — タイトル脇の日付 `19px`、参加者の人数 `20px`。いずれも Tailwind arbitrary value で再現可能なため、**実コードのトークン追加はしない**方針で確定。`28px`＝`--kg-text-2xl`、`15px`＝`--kg-text-base` と同値なのでトークンを使う
- **既存プリミティブと寸法が違う新バリアント:** ボタン sm が 30px（既存 `Btn size="sm"` は h-8=32px）、角丸 `--kg-radius-md`（既存 Btn は rounded-lg）、メールカード角丸 8px（既存 `Card` は 10px 固定）。既存プリミティブを変更せず、この画面用の派生として実装する
- **ダークテーマ:** 実コードに存在しない（ライトのみ）ため対象外
- **日付表記:** `8/5(水)` 形式は `/events` 一覧の表記と揃える

## 10. 残課題・実装への申し送り

- **★タップ領域（受容済みリスク）:** テキストリンク化したアクションの実測高が **17〜19px**（未申込に戻す / 要綱を再送 / 連携解除 / 再配信 / 未送信の級へ配信 / URL を編集）、「編集」リンクが 16px で、iOS 推奨 44px を下回る。**見た目を変えずに当たり判定だけ広げる**（padding ＋ 相殺の negative margin、または `::before` で拡張）ことを実装時に検討する。特に「連携解除」は破壊的操作なので、confirm ダイアログは現行どおり必ず残すこと
- 級タブ 33px・トグル summary 36〜43px は許容範囲
- **sticky ヘッダー 163px** が常時画面の 23% を占める（トグル閉で全長が管理者 1074px まで縮んだ効果とのトレードオフ。意図的に採用）
- **既存テストへの波及:** この画面の作り替えで `RosterSection.test.tsx` / `EventLifecycleSection.test.tsx` / `LifecycleStatusBadge.test.tsx` / `actions.roster.test.ts` などが影響を受ける。テスト破壊は承認必須（CLAUDE.md 開発ルール5）
- **オープンチャット欄は別スコープ**（下記「スコープ外」参照）

## スコープ外（別 feature として切り出し）

- **オープンチャット欄** — ユーザー判断で別スコープ。`line.me/ti/g2` 形式の URL を保持するカラムは DB に存在せず（全文検索で該当ゼロ。`apps/web/src/lib/broadcast-lead-presets.ts:13` に文言があるだけ）、**スキーマ追加＋migration が必要**。モックには UI 案として残置し、HTML に `SCOPE-OUT:` コメントを入れて実装時に拾わないようにしてある。級別/全級の運用切替・URL 編集 UI・会員には自分の級のみ表示、という仕様も未定義
