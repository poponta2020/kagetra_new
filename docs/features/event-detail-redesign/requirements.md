# 大会申込詳細（/events/[id]）リデザイン 要件定義書

> **改修モード（delta）。** devflow 導入前の実装で requirements.md が無かったため、
> 現行実装から起こしたベースラインを §8 に残す（レビュー・出荷時の照合用）。
> **画面レイアウトはここに書かない** — 視覚の正は
> [`design-spec.md`](design-spec.md)（`status: locked`）と `design-mock/redesign.html`。

## 1. 概要

### 目的
`/events/[id]`（大会申込詳細）を、管理者ビュー・一般会員ビューとも
**「罫線＋余白主導（脱カード）」** へ作り替える。既定表示では、会員も管理者も
「どの大会か・今どの段階か・自分は出るか」だけが見える状態にする。

### 背景・動機
- 管理者ビューが 13 ブロックの縦積みで極端に長く、「会員が読む情報」と「運営操作」が交互に混ざる
- カードの入れ子で情報が箱に埋もれる（`docs/design/design.md` 2.5 アンチスロップ規約に反する）
- 日付が生 ISO 表記（`2026-09-06`）のまま
- 申込がどの段階にあるか（会内締切・申込・抽選・支払・開催）を一目で掴む手段が無い

### 効果（design-spec の実測）
トグル閉の初期表示で、ページ全長が **会員 764px / 管理者 1074px**（スクロール内寸 716px）。
会員ビューはほぼ1画面に収まる。

## 2. ユーザーストーリー

改修モードのため再聴取はしない。現行の利用実態を確認したもの:

- **一般会員**: 出るかどうかを決める／名簿で自分の掲載を確認する／今どの段階かを知る
- **管理者・副管理者**: 会としての申込・支払の進行を管理する／LINE 配信の状態を見る／
  自分自身の出欠も同じ画面で回答する

## 3. 機能要件

### 3.1 画面と遷移

- 対象は `/events/[id]` の1画面のみ。**新しい画面・新しい遷移は増やさない**
- 画面内の開閉（`<details>`）と名簿の級タブはクライアント状態。URL には反映しない
- 遷移の変更: 「← イベント一覧」の戻りリンクを**廃止**する。一覧へはボトムナビの
  「イベント」タブで戻る（nav-settings-hub 後もこのタブは残る）
- 見た目・セクション構成・状態ごとの見え方は **design-spec.md と `design-mock/redesign.html` が正**

### 3.2 ビジネスルール

#### 3.2.1 申込フロー（新設）

**会内締切 → 大会申込 → 抽選 → 支払 → 開催** の5ステップを横一列に描く。両ビュー共通。

- **5ステップは常に描く。** 対応する日付が NULL でもステップを消さず、日付欄に `未定` と出す
- **判定はハイブリッド**（ステップの性質に応じて判定元を変える）:

| ステップ | 完了(done)の判定 | 日付欄 |
|---|---|---|
| 会内締切 | `internalDeadline` < 今日（JST） | `internalDeadline` |
| 大会申込 | `entryStatus === 'applied'` | `entryDeadline` |
| 抽選 | `lotteryDate` < 今日（JST） | `lotteryDate` |
| 支払 | `paymentType === 'advance'` かつ `paymentStatus === 'paid'` | `paymentDeadline` |
| 開催 | `eventDate` < 今日（JST） | `eventDate` |

- **中立(neutral)** = 判定の対象外にするステップ。完了でも警告でもなく、**現在地の候補にもならない**:
  - **支払ステップ**: `paymentType !== 'advance'`（現地払い／未設定）。事前払い以外は支払状態を
    持たないため。日付欄は `onsite` なら `現地払い`、`null` なら `未定`
  - **`entryStatus === 'not_applying'` のとき**: 大会申込・抽選・支払の3ステップ。
    大会申込の日付欄は `申込なし` にする
- **現在地(now)** = 完了でも中立でもないステップのうち最も先頭のもの。**高々1つ**
  - `entryStatus === 'not_applying'` のときは **現在地を出さない**（会として申し込まない以上、
    「進行中の段階」が存在しないため）
  - 候補が1つも無い（全て完了または中立）ときも現在地を出さない
- **警告(warn)** = **期限を過ぎているのに未完了**のステップ。すなわち
  - 大会申込: `entryDeadline` < 今日 かつ `entryStatus !== 'applied'`
  - 支払: `paymentDeadline` < 今日 かつ `paymentType === 'advance'` かつ `paymentStatus !== 'paid'`
  - 日付が NULL のステップ・中立のステップは warn にならない
  - warn は now と併存しうる（期限超過の未完了ステップが現在地でもある場合）
- **開催(goal)** は常に goal の見た目。完了していても goal スタイルを保つ

#### 3.2.2 一般会員から見えなくなる情報（削除）

以下は**一般会員には描画しない**（RSC payload にも載せない）:

- 参加費・支払締切・支払方法・支払情報（振込先）
- 申込方法

→ これらは**管理者の「支払状態」「申込状態」トグル内**に集約する。
会員がこれらを知る経路は **LINE グループへ配信される要綱**（および管理者への問い合わせ）とする。
会の運用として参加費の周知は要綱配信で足りている、というユーザー判断による。

#### 3.2.3 画面から削除する表示

**(a) セクションごと無くなるもの**（情報の一部は別セクションへ移る）:

| セクション | 扱い |
|---|---|
| 詳細表（DescList の14行） | 廃止。残す情報は申込フロー・級別定員・進行管理トグルへ再配置 |
| 出欠状況カード（参加/不参加の2枚） | 廃止。参加人数は「参加者」セクションの見出しへ移す |
| 進行状況（**一般会員向けの読み取り専用バッジ** `LifecycleStatusBadge`） | 廃止。申込フローが役割を引き継ぐ |
| LINE 配信（一般会員向けの1行案内） | 廃止。会員には LINE 配信の有無を見せない |
| コメント（出欠コメントの折りたたみ） | 廃止 |
| 級別グループ配信（管理者の独立セクション） | 廃止。**LINE 配信トグルの中の1項目へ移す**（`role === 'admin'` 限定は維持） |
| 名簿の Excel 取込フォーム | 廃止（§3.2.6） |
| 関連メール | **管理者のみ残す**。独立セクションから開閉トグルへ変更 |

**(b) フィールド単位で削除するもの**（両ビュー）:

- 「← イベント一覧」戻りリンク
- 公認ピル／中止・終了のステータスピル／主催／正式名称
- 申込日時・支払日時の表示、LINE 未紐付け時の注記
- 名簿の「会員」バッジ（所属の後ろの藍の添え字へ置換）

**(c) 算出をやめるもの**:

- **不参加人数（`nonAttendingCount`）の算出と表示**
- ただし `eligibleUsers` のクエリ自体は**残す** — 参加者リストから対象級外の stale 行を
  除外するのに必要（§6 の回帰契約）

> 出欠コメント自体はデータとして残す（`event_attendances.comment` は削除しない）。
> `submitAttendance` の comment 更新経路も残すが、この画面から呼ぶ UI は無くなる。

#### 3.2.4 対象級・級別定員

`eligibleGrades` の行（旧「対象級」）を独立表示せず、**級別定員のセクションに統合**する。

- `capacityA`〜`capacityE` に値がある級は「級 + 定員数」を横並びで出す
- **定員が1つも設定されていない大会**では、`eligibleGrades` の級だけを同じ並びで出す（数字なし）
- `eligibleGrades` も定員もどちらも無い（＝全級対象・定員未設定）大会では、**セクションごと非表示**
- 合計（「計 N名」）は定員がある場合のみ出す

#### 3.2.5 名簿

- **級の若い順（A→B→C→D→E、級なしは最後）に並べ替える**（現行は取込順）
- **級タブ**（全体 / 対象級ごと）で絞り込む。**初期選択は「全体」固定**
  （会員の級を初期選択にはしない — 管理者・会員で挙動を分けず、予測可能にする）
- タブに件数を出す。件数は表示中の名簿の entries を級で集計した値
- 確定名簿が未取込のときの文言は
  **「まだ取り込まれていません。メール取り込みで登録されると、申込者名簿と同じ形式で確定した出場者が並びます。」**
- 会員突合済みの行は名前を藍にし、所属の後ろに「・会員」を添える（バッジは使わない）
- **個人戦のみ表示**する現行ルールは維持する

#### 3.2.6 名簿の Excel 取込を廃止

- この画面の取込フォーム（`RosterUploadForm`）と Server Action `uploadRoster` を**削除**する
- 名簿は**メール取り込み経由のみ**とする。承認 UI（`/admin/mail-inbox/roster-drafts/[id]`）で
  `applicant` / `confirmed` の両方を取り込めることを確認済み。発行日の入力・訂正版の指定も
  メール側が上位互換
- **団体戦ガードの移植はしない**（ユーザー判断）。`uploadRoster` にあった
  `kind !== 'individual'` チェックは削除とともに失われるが、団体戦に名簿を取り込む運用が
  無いため許容する

#### 3.2.7 進行管理の操作

- 「申し込まない」ボタンは **`entryStatus === 'not_applied'` のときだけ**表示する
  （現行は `applied` のときにも出ていた）。`applied` から直接 `not_applying` へは遷移せず、
  「未申込に戻す」を経由する2手順になる
- `not_applying` のときは「未申込に戻す」のみ（現行どおり）
- 状態変更に伴う LINE 通知・once-ever の挙動は**一切変更しない**

#### 3.2.8 日付表記

- **生 ISO 表記（`2026-09-06`）を画面に出さない**
- 文脈ごとの書式は design-spec §8 の対応表に従う（大会名脇とフラット表は `9/6(日)`、
  申込フローは `7/31`、LINE 連携状況は `2026/07/20 14:32`、配信履歴・発行日は `7/25 18:02`）
- `/events` 一覧の `formatEventDate` と**同じ実装を共有する**（現在は一覧専用モジュール）

#### 3.2.9 ページ余白

- ルート要素に `p-4` を持たせる。**`<main>` には padding を足さない**
  （PR #345 の回帰ガードを維持）
- **nav-settings-hub が `/events/[id]` に `p-4` を入れる差分を持っている。**
  同機能を先に出荷するため、本改修はその結果を引き継ぐ（二重に入れない）

- `/admin/entries` への「申し込まない」導線の新設
- 出欠コメントのデータ削除・`submitAttendance` の comment 経路の削除
- `/events` 一覧・ダッシュボード等、他画面の変更（日付整形の共通化に伴う移動を除く）
- ダークテーマ対応（実コードに存在しない）

## 6. 技術的制約・契約

### 実装順序の制約 ★
- **`nav-settings-hub`（親Issue #346）の出荷後に実装する。** 同機能は `/events/[id]` の
  ルート要素に `p-4` を入れる差分を持ち、上部バー 44px を廃止してボトムナビを再構成する
  （一般会員4タブ・管理者6タブ）。先に出荷させ、本改修はその土台の上に作る
- `design-mock/redesign.html` が描く上部バー（44px）とボトムナビ（管理者7タブ）は
  **確定当時のシェルであり、忠実度チェックリストの対象外**。実装時点の現実に合わせる
- **この順序を散文だけに頼らず、機械的に持ち回る**（散文は誰も読まずに `/implement` が走るため）:
  - 親 Issue のタイトルに `（#346 出荷後に着手）` を入れ、本文の冒頭にブロッカーを明記する
  - `implementation-plan.md` の**先頭タスクの `依存タスク:` に `nav-settings-hub（親Issue #346）の出荷`** を書く

### 変更してはいけない挙動（回帰の契約）
- 出欠回答の可否判定・集計ロジック（ドメインルール「未回答＝不参加」）
- 進行管理の状態遷移と LINE 完了通知の once-ever 契約
- 一般会員への RSC payload に管理者専用情報を載せない（`LineBroadcastSection` の
  status のみスタブ方式を維持）
- 級別グループ配信は `role === 'admin'` 限定（`vice_admin` を含めない）
- 名簿は個人戦のみ

### 技術的な前提（調査で確定）
- **`session.user.role` は実効ロール**（role-preview-switch 出荷後）。表示の出し分けは
  これを読む。`realRole` は復帰導線の認可専用で、表示判定に使わない。
  → この画面は**既にプレビューへ追随済み**。追加対応は不要
- **`<main>` に padding を足さない**（PR #345 の回帰ガード `mobile-shell.test.tsx`）。
  余白は各ページ根要素の `p-4` で完結させる
- **`formatEventDate`**（`events/event-list-utils.ts`）は `/events` 専用。共有するには
  共通モジュールへ切り出す必要がある
- **`materializeRoster` / `parseRosterGrid` / `readExcel` は共有ライブラリ**（メール取込も使う）。
  削除するのは `uploadRoster` 関数と `RosterUploadForm` コンポーネントのみ
- 削除で整理が必要なテスト: `actions.roster.test.ts`（ファイルごと削除）、
  `RosterSection.test.tsx` の `uploadRoster` モック（死にモック）
- Server Action は冒頭で `auth()` ＋ role チェック。データ変更後は `revalidatePath()`

### 未解決の技術論点（技術計画フェーズで解決する）

## 7. 設計判断の根拠

- **脱カード**: カードを1枚はがしても情報は読めた（`design.md` 2.5 のリトマス試験に不合格）。
  箱は構造を作っておらず、画面が長い主因でもあった
- **申込フローのハイブリッド判定**: ステップの性質が混在している。大会申込と支払は状態
  （`entryStatus` / `paymentStatus`）を持ち、会内締切・抽選・開催は日付しか無い。
  どちらか一方に倒すと、状態を持つステップの実態（締切後の未申込・期限前の支払済）を
  表現できない
- **警告を「期限超過かつ未完了」に限定**: 単に「未払」を警告にすると、支払期限まで日がある
  通常状態が常に警告になり、朱が意味を失う
- **級タブの初期選択を「全体」固定**: 管理者と会員で初期状態を変えると挙動が予測しにくい。
  自分の掲載有無は別途1行で表示されるため、自分の級を初期選択にする必要が無い
- **対象級を級別定員へ統合**: 対象級の独立行は削除されたが、定員未設定の大会で
  「どの級が出られるか」が分からなくなる欠落を、同じ並びで埋める
- **参加費を会員から隠す**: 要綱の LINE 配信で周知が足りているというユーザー判断。
  画面の役割を「出るか決める」に絞る
- **団体戦ガードを移植しない**: 団体戦に名簿を取り込む運用が無いというユーザー判断
- **nav-settings-hub を先に出荷**: あちらは要件・計画・patch まで完成して実装待ち。
  先に出せば本改修は確定した土台の上に作れ、余白の二重定義も起きない

## 8. 現行挙動のベースライン（改修前・照合用）

> devflow 導入前の実装から起こした事実。**変更後の姿は §3 が正**。

### 8.1 画面と権限
- `isAdmin` = `role` が `admin` または `vice_admin`／`isStrictAdmin` = `admin` のみ（級別配信）
- 不正 id・存在しない id は `notFound()`。**ステータスによるアクセス制限は無い**
  （`not_applying` も締切超過も URL 直打ちで到達できる）

### 8.2 セクション構成
管理者: 戻る/編集 → タイトル+公認ピル → 詳細表 → 詳細文 → 出欠状況 → 進行管理 →
LINE 配信+配信履歴 → 級別グループ配信 → 名簿+Excel取込 → 関連メール → 参加者 →
コメント → 参加ボタン(sticky)

一般会員: 編集無し／進行管理→読み取り専用バッジ／LINE 配信→1行案内／
級別配信・関連メール→非表示／名簿→閲覧のみ

### 8.3 主なルール
- **出欠回答**: `canRespond` = ログイン済み かつ（`isAdmin` または（`isInvited` かつ 会内締切内
  かつ 対象級））。管理者は締切・級・招待をバイパス。会内締切は JST 日付比較で当日は可。
  コメントは `comment` フィールド送信時のみ更新
- **出欠集計**: 分母＝`isInvited=true` かつ対象級のユーザー数。参加＝`attend=true` かつ
  現在の対象級。不参加＝分母−参加（未回答を含む）
- **進行管理**: `entryStatus` 3状態。`applied` 初回遷移のみ通知2通（参加者・会計）、
  `paid` 初回遷移のみ通知1通。すべて once-ever。`cancelled` には送らない。
  `not_applying` は通知なしで、**この画面が唯一の設定入口**
- **LINE 配信**: 4状態。一般会員には status のみのスタブ。履歴は最新20件、
  `failed`/`partial` から再配信可
- **級別グループ配信**: `admin` のみ。再送は未送信の級だけに届く
- **名簿**: 個人戦のみ。`supersededAt IS NULL` の最新版。確定を上・申込者を下。
  管理者は Excel 取込フォームを持つ
- **関連メール**: 3経路 UNION を受信日降順。0件なら非表示。`isAdmin` のみ
- **表示**: ページ余白ゼロ／日付は生 ISO ／カード13ブロック縦積み
