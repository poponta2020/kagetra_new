## 1. 対象と狙い
- **対象画面:** 上記 frontmatter の6画面（＋S2/S3/S4 は既存パターン踏襲で試作なし。§10）
- **現状の不満:** 遠征届の材料（行程・学部・学年・電話）を提出係が LINE で聞き集めて Word に転記している
- **狙い:** 対象者が「開いて保存するだけ」で行程が入り、提出係は「そろった」通知→「作成」→ダウンロードで済む
- **主ユーザー / 主な使い方:** 対象者（会員・ゲスト）＝自分の行程を入れる／提出権限者＝進捗を見て作成する／管理者＝確定状況を入れる

## 2. 採用した方向性
- **方向性:** S8 は**案A（日ごとのタイムライン）**。前日〜翌日を1日1行に並べ、既定の往路・復路が入った状態で開く。行き・帰りは3択ずつ（札幌／帰省先／その他＝地名の自由記述）
- **不採用案と理由:** 案B（往路・復路の2カード）— 初見は軽いが、途中の移動を足すと結局 案A の行になる＝案A の部分集合。R1 で提示し R2 で不採用
- **視覚の正:** `design-mock/`（カード: 遠征届（travel-report） 配下の5枚）
  - `route-input.html` — S8（初回既定／帰省先から出場＋そのまま帰省／その他／プロフィール欠落の断片／入力済み・代理入力）
  - `day-home.html` — S7 日ページ＋S9 ホーム（未入力 CTA／入力済み／提出権限者の断片）
  - `group-section.html` — S5 遠征届セクション＋確定状況（入力開始済み／確定状況3択／未開始・不要・一般会員の断片）
  - `create.html` — S6 作成画面（ファイル分割／届の内容／共通／1単位・統合後の断片）
  - `register.html` — S1 登録フォーム（会員用 全日協あり／会員用 D・E級／ゲスト用）
- **最終確認時の状態:** R3（2026-09-06）。全 HTML を 1260〜2080px 幅で PNG 化し横スクロール無しを確認

## 3. 視覚の正に現れない設計判断
- **S8 の既定行は本人の出場日基準**（最初の出場日の前日／最後の出場日の翌日）。単位の初日・最終日ではない（requirements R6）
- **S8 の出場チップは触れない**（出欠から導出。チップの文言は行き＝帰省先から出場 のときだけ変わる）
- **S8 のプロフィール行は表示のみ**。欠けている項目があるときだけ「あなたの情報」の表を開いた状態で始め、保存でプロフィールへ書き戻す
- **S7 のセクション位置はグループ導線の直下**（参加者より上）。未入力の人が最初に見る位置。出すものが無い一般会員にはセクションごと出さない
- **S9 の行は未回答アラートと同型の朱**（「自分が手を動かす必要がある」の色）。右端は「未入力」固定
- **S5 の確定状況は名簿セクション内の開閉行**。キャンセル待ち＝琥珀（warn）、不参加＝藤鼠（neutral）で塗る
- **S5 の未入力者は朱の名前がそのまま代理入力導線**。別ボタンを置かない
- **S6 の分割操作は「日をファイルNへ」「隣接ファイルと統合」の2操作だけ**。ドラッグはしない。統合で週をまたぐと警告
- **S6 で編集できるのは 目的・場所・遠征先連絡者・留守連絡先・届の日付・承認日 だけ**。名簿・備考は生成のみ（直すなら Word）
- **S1 の電話・生年月日は全日協ブロックと同じ欄を共用**。全日協ブロックが出るときはそちらに「共通」と添えて1回、出ない級ではサークル所属ブロック内に出す

## 5. 状態（state）
- **S8 通常:** 既定行あり（`route-input.html` 1枚目）。**帰省先から出場＋そのまま帰省:** 既定行なし・チップ文言変化（2枚目）。**その他:** 地名入力が開き、既定行がその地名（3枚目）。**プロフィール欠落:** 表が開いた状態（断片）。**入力済み・代理:** 見出しに対象者名と朱の注記、バッジ「入力済み M/D hh:mm」、ボタン「修正を保存」（5枚目）
- **S7:** 未入力（朱 CTA）／入力済み（藤）／提出権限者（＋原本行・グループページ導線）／出すものが無い（セクション非表示）
- **S9:** 未入力の遠征単位ごとに1行。0件なら何も出ない（既存の未回答アラートと同じ）
- **S5:** 未開始（トグル・開催地・開始ボタンのみ）／入力開始済み（単位ごとの進捗・作成・履歴・原本）／不要（トグルだけ。履歴があれば件数リンク）／一般会員（単位ごとの `n/m` のみ）／確定状況（開閉行）
- **S6:** 1単位（1ファイル）／2単位（2ファイル・未入力警告）／統合後（長期間警告）
- **S1:** 会員（全日協あり）／会員（D・E級＝全日協ブロックなし）／ゲスト（姓・名が増える）
- **各状態の確認先:** 上記ファイル名（Claude Design push 後は同名カード）

## 6. 必要データ
- **表示フィールド:** requirements §3.2 のとおり。S8 = 対象者の出欠「参加」の日・行き／帰り・移動行・プロフィール（学部区分・学部等名・学年・電話）・開催地（経路表記名）。S5 = 遠征単位ごとの対象者と入力済み判定・確定状況・履歴（ファイル名・作成日時・作成者）・副連絡責任者名。S6 = 遠征単位・ファイルごとの既定値（目的・場所・連絡者2・日付2）・名簿人数・備考行数・未入力者
- **仮データのまま確定した項目 ★実装で必ず実配線する:** モックの人名・大会名・地名・日付・電話番号はすべて架空。「備考 7行」「期間 11/6〜11/9」等の見込み値は生成ロジックから算出する。AI推定バッジは推定元が AI のときだけ出す（手修正後は消す）
- **集計・導出:** 遠征単位＝連続開催日の分割（純関数）。入力済み `n/m`＝対象者数と保存済み件数。S6 の期間＝そのファイルの出場者全員の行の最小日〜最大日

## 7. インタラクション / レスポンシブ
- **S8:** 行き／帰りの選択で既定行だけ差し替え（本人が足した行は残す）。「その他」を選ぶと直下に地名入力。移動行の削除は行右端の「×」。日の追加は両端のリンク。保存は sticky ボタン（出欠回答ボタンと同じ位置）
- **S5:** 確定状況はセグメントをタップ→「確定状況を保存」でまとめて保存。未入力者の名前タップ＝代理入力（S8 を対象者指定で開く）
- **S6:** 「ファイルNへ」で日を移動、統合バーで隣接ファイルを1つに。「N ファイルを作成する」は sticky
- **モバイル:** 375px 基準。S8 の移動行は入力2つ＋矢印＋×が1行に収まる（各入力は 40% 幅）。S5 の顔ぶれは折り返し。横スクロール無し（全モック PNG で確認）
