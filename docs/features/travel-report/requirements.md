# travel-report（遠征届）要件定義書

## 1. 概要

- **目的**: 北海道大学かるた会のサークル所属者が大会に出場するとき大学へ提出する「遠征届」（Word）を、会員が入力した遠征経路とプロフィール属性から自動作成し、提出係（副連絡責任者）へ LINE で知らせる。
- **背景・動機**: 北大かるた会（北海道大学のサークル）のメンバーは、サークル活動として大会に参加する際に「遠征届・合宿届」を大学へ提出する必要がある。現状は提出係が各人の行程・学部・学年・電話を聞き集めて Word に手で転記しており、名簿確定のたびに大きな負担になっている。原本は `docs/遠征届資料/遠征届原本2025.dotx`、記入例は同フォルダの青森大会分。
- **範囲（1 PR）**: ①副連絡責任者・サークル長フラグ ②サークル所属と学部・学年・電話・生年月日の属性 ③遠征経路の入力画面と未入力導線 ④遠征届の作成・保存・ダウンロード・LINE 通知 ⑤名簿確定時の「確定状況（確定／キャンセル待ち／不参加）」入力（遠征届の対象者判定のため。第2弾 35 で追加）⑥原本ダウンロード導線 ⑦遠征届設定（顧問教員）。

## 2. ユーザーストーリー

| 役割 | この機能での関心 |
|---|---|
| サークル所属の会員・ゲスト | 出場が確定した大会について、自分の行程（いつ・どこからどこへ動くか）と学部・学年・電話をアプリで入れるだけで済ませたい。未入力なら気づける |
| 副連絡責任者（提出係） | 全員分がそろったら LINE で知りたい。任意のタイミングで「作成」を押すと Word ができ、確認して大学へ提出したい。遠征を伴わない大会は対象外にしたい |
| 管理者・副管理者 | 名簿が確定したら誰が確定・キャンセル待ちかを入れ、繰り上がりも反映したい。副連絡責任者と同じ操作（作成・代理入力・対象外切替）もできる |
| 新規登録者 | 登録時にサークル所属と学部・学年を入れておけば、以後の遠征届で聞かれない |

**利用シナリオ**

1. 管理者が会員編集画面で提出係に「副連絡責任者」、主将に「サークル長」を付ける。設定ハブの「遠征届」で顧問教員を確認する
2. 会員・ゲストは登録時に「北大かるた会サークルに所属」を選び、学部等名・学年・電話・生年月日を入れる（既存会員は管理者が会員一覧の一括編集で投入）
3. 大会の確定名簿が出たら、管理者が申込グループページの名簿セクションで各人を確定／キャンセル待ち／不参加にする。名簿確定により経路入力が開く（または副連絡責任者・管理者が「経路入力を開始」を押す）
4. 対象者は日ページの「遠征経路を入力する」から、既定で埋まった行程（前日 札幌→開催地、出場日、翌日 開催地→札幌）を確認・修正して保存する。ホームにも未入力の導線が出る
5. 全員分がそろうと大会別 LINE グループに @副連絡責任者 つきで通知が届く
6. 副連絡責任者（または管理者）がグループページの「遠征届」セクションで「作成」を押し、ファイル分割（連続開催日ごと）・目的・場所・連絡先・日付を確認して作成する。docx が保存され、LINE グループに @副連絡責任者 つきで通知が届く。履歴からダウンロードして大学へ提出する
7. キャンセル待ちが繰り上がったら管理者が確定に変えると、その人が対象者に加わり未入力導線が出る。そろえば再通知、必要なら再作成する

## 3. 機能要件

### 3.1 画面と遷移（画面インベントリ＋ナビゲーション地図。見た目は design-spec 参照）

| # | 画面 | 追加・変更 |

| S1 | 招待登録 `/register/[token]`（会員用・ゲスト用） | 「北大かるた会サークルに所属」チェック。ON で 学部/大学院の区分→学部等名（候補つき入力）→学年、電話、生年月日 が必須。ゲスト用はさらに 姓・名（漢字）が必須。電話・生年月日は全日協の項目と同じ入力欄を共用（どちらの条件でも1回だけ表示） |
| S2 | 会員編集 `/admin/members/[id]/edit` | プロフィールに サークル所属・学部区分・学部等名・学年（ゲストは姓・名も）を追加。フラグ「副連絡責任者」「サークル長」のチェック（会計と同じ流儀） |
| S3 | 会員一覧 `/admin/members` | 副連絡責任者・サークル長のバッジ。「一括編集」でサークル所属・学部区分・学部等名・学年を複数人まとめて保存 |
| S4 | 設定ハブ `/settings` → 遠征届設定 `/settings/travel-report` | 顧問教員（所属部局等・職・氏名）。副連絡責任者・管理者・副管理者が編集。初期値は原本の値 |
| S5 | 申込グループページ `/admin/entries/[groupId]` | 名簿セクションに「確定状況」（出欠「参加」の会員・ゲストごとに 確定／キャンセル待ち／不参加。管理者・副管理者）。新設「遠征届」セクション: 必要/不要トグル・開催地（AI推定値の表示と修正）・「経路入力を開始」・遠征単位ごとの入力状況一覧（未入力者に代理入力導線）・「遠征届を作成」・作成履歴とダウンロード。セクションの閲覧は全ロール、操作は副連絡責任者・管理者・副管理者 |

| S7 | 日ページ `/events/[id]` | 新設「遠征届」セクション。対象者に「遠征経路を入力する」（未入力は強調、入力済みは「確認・修正」）。提出権限者にはさらに原本（.dotx）ダウンロードとグループページの遠征届セクションへの導線。出すものが無い人（対象外の一般会員・未開始・不要）にはセクションごと出さない |
| S8 | 遠征経路 入力画面（S7・S5 から遷移） | 1つの遠征単位について本人（代理時は対象者）の行程を入力。行き（札幌から／帰省先から出場／その他＝地名を自由記述）と帰り（札幌へ戻る／そのまま帰省／その他＝地名を自由記述）の選択。日ごとの行: 移動（出発地→到着地）／大会出場（名簿から自動・編集不可）。前後の日の追加。学部等名・学年・電話はプロフィール値を1行で表示し「修正」で編集、欠けていれば入力欄が開いた状態で始まる。「保存」 |
| S9 | ホーム `/dashboard` | 未回答アラートと同じ位置に「遠征経路が未入力」の導線（対象者・未入力の遠征単位ごと）。ゲストはホームに入れないため S7 のみ |
| S10 | ダウンロード route | 生成 docx／原本 dotx（どちらも副連絡責任者・管理者・副管理者のみ） |

### 3.2 ビジネスルール

#### R1. サークル所属と属性

- `サークル所属` は会員・ゲスト共通の真偽属性。既定 OFF。本人が登録時に入力し、以後は管理者が S2/S3 で変更する（本人のプロフィール編集画面は今回作らない）。学部等名・学年・電話はプロフィール（DB）に持ち、S8 ではその値を表示するだけ。欠けているときだけ S8 で入力を求め、保存するとプロフィールへ書き戻す（本人が「修正」から直すこともできる）。
- サークル所属 ON のとき必須: 学部区分（学部／大学院）・学部等名・学年・電話・生年月日。ゲストはさらに 姓・名（漢字）。かなは不要。OFF のときこれらは任意（既存値は保持）。サーバー側で不変条件を強制する。
- 電話・生年月日は既存の全日協用の値と**同一の項目**。全日協 ON とサークル所属 ON のどちらか一方でも該当すれば必須で、入力欄は1つ。別々の番号は想定しない。
- 学部等名は候補つきの自由入力。候補は区分で切り替え、候補外の文字列も保存できる。学年は選択のみ。
  - 学部: 総合教育部・文学部・教育学部・法学部・経済学部・理学部・医学部・歯学部・薬学部・工学部・農学部・獣医学部・水産学部
  - 大学院: 文学院・教育学院・法学研究科・情報科学院・水産科学院・環境科学院・理学院・農学院・生命科学院・国際広報メディア・観光学院・保健科学院・工学院・総合化学院・経済学院・医学院・歯学院・獣医学院・医理工学院・国際感染症学院・国際食資源学院・公共政策学教育部
  - 学年: 学部は「1年」〜「6年」、大学院は「修士1年」「修士2年」「博士1年」〜「博士4年」「専門職1年」〜「専門職3年」。届にはこの文字列をそのまま出力する
- 学年と学部等名の組合せは制約しない（1年生でも学部を選べる）。年度初めの学年更新は運用（本人が S8 で直す、または管理者が S3 で直す）。

#### R2. 役割フラグ

- `副連絡責任者`: 複数可。**通知先の識別と、遠征届に関する操作（必要/不要切替・経路入力の開始・代理入力・作成・ダウンロード・開催地の修正・遠征届設定の編集）の認可の両方に使う**。ロールは一般会員のままでよい。管理者（admin）・副管理者（vice_admin）は常に同じ操作ができる。以下「提出権限者」＝副連絡責任者 ∪ 管理者 ∪ 副管理者。
- `サークル長`: **同時に1人だけ**。会計・副連絡責任者と併存可。付与時に既に別の人が持っていればエラーで拒否する（先に外してから付ける。無言で付け替えない）。届の「団体代表者」と「留守連絡先の既定」に使う。
- 付与・剥奪はどちらも会員編集画面で管理者・副管理者が行う（会計フラグと同じ）。会員一覧にバッジを出す。

#### R3. 確定状況（名簿確定時の入力）

- 申込グループ単位 × 人で「確定／キャンセル待ち／不参加」を持つ。対象は当該グループのいずれかの日に出欠「参加」と答えた会員・ゲスト。管理者・副管理者が S5 の名簿セクションで保存する。
- **有効な確定状況**の導出順: 手入力があればそれ → 無ければ取り込み済み確定名簿の結果（確定・繰上げ=確定、補欠=キャンセル待ち、落選=不参加） → それも無ければ「確定」。画面の初期表示もこの導出値。
- キャンセル待ち→確定（繰り上げ）はいつでも変更できる。参加費・振込への反映はしない（運用）。繰り上がった人は即座に遠征届の対象者になる。
- 確定状況の入力は「確定名簿あり」判定（申込管理ボードのフェーズ）を変えない。今回はこの値を遠征届の対象者判定にのみ使う（他機能への波及は §5）。

#### R4. 対象大会と遠征単位

- すべての申込グループは既定で「遠征届 必要」。提出権限者はいつでも「不要」に切り替えられ、「必要」へ戻せる（入力済みデータは保持）。「不要」の間は S7/S9 の導線・LINE 通知を出さず、S5 の遠征届セクションは「不要」表示と戻すボタンだけになる。
- **遠征単位**＝グループ内の開催日を日付順に並べ、連続する日をまとめたもの（第1土日と第2土日なら2単位）。経路入力・入力状況・全員そろった通知はこの単位。作成時のファイル分割の既定もこの単位で、S6 で日単位に統合・分割できる（級では分けない）。
- 団体戦グループも同じ扱い（追加の特別対応はしない）。

#### R5. 経路入力の開始と対象者

- 経路入力が**開いている**とは、グループが「必要」かつ（「確定名簿あり」判定が成立している、または提出権限者が「経路入力を開始」を押した）状態。開く前は S7 にボタンを出さず、保存も拒否する。
- **対象者**（遠征単位ごと）＝ サークル所属 ON ∧ その単位のいずれかの日に出欠「参加」 ∧ 有効な確定状況が「確定」。会員・ゲストの両方。
- **入力済み**＝その単位についてその人の経路が1回以上保存されている（移動0行でも可）。
- 「経路入力を開始」時に開催地が未設定なら R7 の AI 推定を行う。

#### R6. 経路の構造

- 1人 × 1遠征単位の経路 = **行き**（`札幌から`／`帰省先から出場`／`その他`＋地名の自由記述）＋ **帰り**（`札幌へ戻る`／`そのまま帰省`／`その他`＋地名の自由記述）＋ 移動行の並び。移動行＝日付・出発地・到着地（地名は自由入力、同じ日に複数行可、日付は単位の前後に自由に足せる）。
- 大会出場の行は保存せず、その人の出欠「参加」の日から導出する。表記は「大会出場」、行きが `帰省先から出場` のときだけ「大会出場（帰省先から出場）」。`その他` は出場表記を変えず、移動行で表す。
- **既定の行程（初回表示）は本人の出場日を基準**にする（遠征単位の初日・最終日ではない）:
  - 行き `札幌から` → 本人の最初の出場日の前日に「札幌→{開催地}」。`帰省先から出場` → 往路の既定行なし。`その他` → 前日に「{地名}→{開催地}」
  - 帰り `札幌へ戻る` → 本人の最後の出場日の翌日に「{開催地}→札幌」。`そのまま帰省` → 復路の既定行なし（備考には出場のあと何も書かない）。`その他` → 翌日に「{開催地}→{地名}」
  - 開催地が未設定なら該当欄は空欄。選択を変えると既定行だけを差し替え、本人が足した行は残す
- 保存者は本人または提出権限者（代理入力）。代理入力は対象者一覧（S5）から対象者を指定して行う。他人の経路を一般会員が保存しようとしたら拒否。
- S8 で欠けているプロフィール項目（学部等名・学年・電話）を入れた場合はプロフィールへ保存する。代理入力時は対象者のプロフィール。

#### R7. 開催地（経路表記用の地名）の AI 推定

- グループ単位に 都道府県・市区町村・経路表記名（例: 八戸）を持つ。「経路入力を開始」時（自動で開いた場合はそのタイミングの最初の処理）に未設定なら、会場（`events.location`）と大会名から Claude で1回推定して保存し、S5 に「AI推定」と表示する。提出権限者はいつでも修正できる（修正後は AI 推定をやり直さない）。
- 推定に失敗した、または会場が空のときは空欄で保存し、手入力を促す。推定失敗で機能が止まらない。

#### R8. 全員そろった通知

- 経路の保存によって、その遠征単位の対象者全員が入力済みに**なった瞬間**に1回だけ、グループに紐付いた大会別 LINE グループへ「@副連絡責任者」メンションつきのテキストを送る（既存の @会計 と同じ仕組み。LINE 未紐付けの副連絡責任者は黙って飛ばし、0人でも素テキストで送る）。既にそろっている状態での再保存では送らない。対象者が増えて未完了に戻り、再びそろったら再送する。
- LINE グループが紐付いていないグループでは送らない（S5 の入力状況で代替）。

#### R9. 遠征届の作成

- 提出権限者だけが作成できる。未入力者がいても作成できる（S6 で警告。未入力者は名簿に載り、備考には出場行のみ）。
- S6 の既定: ファイル分割＝遠征単位。ファイルごとの既定値:
  - 目的: 「{正式名称（無ければ大会名）}({そのファイルの日の対象級を A〜E の順に連結}級)への参加」
  - 場所: そのファイルの日の会場（`events.location`）。複数なら重複を除いて「・」で連結
  - 遠征先 連絡者: そのファイルの出場者のうち、サークル長 → 管理者 → 副管理者 → 副連絡責任者 → 会計 の順で最初に見つかった1人。誰もいなければ生年月日が最も早い人（同日なら全員、2人までを想定）。氏名と電話を出力
  - 留守連絡先: サークル長。サークル長が出場者に含まれるなら、出場しない副連絡責任者（複数なら id 順の先頭）。それもいなければ空欄
  - 届の日付: 作成日（JST）。承認日: 空欄（任意入力）
  - いずれも S6 で修正できる
- 作成物: ファイルごとに docx を生成して版として保存する（作成日時・作成者・含まれる日・ファイル名・ヘッダ値のスナップショット）。履歴はすべて残し、S5 から個別にダウンロードできる。ダウンロードはログイン必須で提出権限者のみ（公開 URL は作らない）。
- 作成後、LINE グループへ「遠征届を作成しました（N ファイル）」＋ S5 への案内を @副連絡責任者 つきで送る（R8 と同じ経路・同じ省略ルール）。
- ファイル名は記入例に倣う（例: `2026.6.13,14 青森大会 遠征届.docx`。具体形式は実装で決める）。

#### R10. 届本体・名簿・備考の埋め方

- テンプレ: 原本 `.dotx` の構造をそのまま使い .docx で出力する（見出し・罫線・フォントを変えない）。出力は docx のみ。
- 期間: そのファイルの出場者全員の行（移動行＋出場日）の最小日を「自」、最大日を「至」、暦日数を「（N日間）」。年は令和に変換（西暦−2018）。届の日付・承認日も令和表記。
- 人数: そのファイルの出場者数。
- 団体名: 「北海道大学かるた会」（テンプレのまま）。団体代表者: サークル長の 学部等名＋学年（例「法学部 2年」）・氏名・電話。サークル長未設定なら空欄。顧問教員: 遠征届設定の3値。「副学長 殿」はテンプレのまま。
- 名簿表: 役職＝空欄、氏名＝姓と名をスペース無しで連結（分割氏名が無い会員は表示名から空白を除いたもの）、学部等名、学年、連絡先＝電話。並び＝学年の高い順（博士4年 → … → 博士1年 → 修士2年 → 修士1年 → 専門職3年 → … → 専門職1年 → 6年 → … → 1年）、同学年はかな順（かなが無いゲストは末尾・氏名順）。41人以上は行を足す（別紙は作らない）。
- 備考: 日付順に1日1段落「M/D [姓、姓]内容 [姓]内容 …」。同一内容（同じ出発地→到着地、または同じ出場表記）の人をまとめ、姓は名簿順。同姓が複数いる人だけフルネーム。同一日内の順は「開催地へ向かう移動 → 大会出場 → 開催地から離れる移動 → その他の移動」。

#### R11. 原本ダウンロード

- 原本 `.dotx` は**提出権限者だけ**が取得できる（S7 の遠征届セクションと S5 の遠征届セクションに導線）。一般会員・ゲスト・未ログインは拒否。
- **同梱するテンプレは原本の団体代表者・顧問教員・電話を空欄にした版**にする（届の作成時はサークル長・設定から埋めるので支障なし。原本の個人情報を git 履歴に残さないため。§7）。

#### R12. 権限まとめ

| 操作 | 会員・ゲスト（本人） | 副連絡責任者 | 管理者・副管理者 |
|---|---|---|---|
| 自分の経路の保存・属性修正 | ○（対象者のみ） | ○ | ○ |
| 他人の経路の代理入力 | × | ○ | ○ |
| 必要/不要・経路入力を開始・開催地修正 | × | ○ | ○ |
| 遠征届の作成・ダウンロード | × | ○ | ○ |
| 遠征届設定（顧問教員） | × | ○ | ○ |
| 確定状況の保存 | × | × | ○ |
| フラグ・属性の付与（S2/S3） | × | × | ○ |
| 原本ダウンロード | × | ○ | ○ |

ゲストは現在 `/events` と `/settings` 系だけ許可されているため、S8（経路入力）をゲストの許可パスに加える。

#### R13. エラー・境界

- 経路入力が開いていない／「不要」／対象者でない人の保存は拒否し、日本語で理由を返す。
- サークル所属 ON で必須項目が欠けた登録・更新は拒否（登録フォームは項目ごとにエラー表示）。
- サークル長の重複付与は拒否（R2）。
- 生成時にサークル長・顧問教員・開催地が未設定でも作成は成功し、該当欄は空欄になる（S6 で警告）。
- 作成物の LINE 通知が失敗しても作成物は保存済みのまま（通知失敗を S5 に表示）。

## 6. 技術的制約・契約

- **互換性**: 既存の登録フロー（全日協の条件付き必須・段位・級）、出欠回答、申込管理ボードの分類、LINE 配信の各機能は現行どおり動くこと（AC-32 の回帰＋各既存テスト）。`users.phone` / `birth_date` は列を増やさず共用する。
- **公開契約**: `/api/external/tournament-entrants` のレスポンス形を変えない（AC-31）。
- **保持データ・移行**: users への列追加、グループ単位の遠征届設定・確定状況・経路・作成物の新テーブルは Drizzle migration で追加する（本番は `db:migrate`）。既存行はサークル所属 OFF・確定状況なし（＝導出で「確定」）で自然に整合する。
- **セキュリティ・権限**: R12 のとおり。副連絡責任者フラグは認可に使う（会計フラグとは扱いが異なることをコード上のコメントで明示する）。生成 docx と経路には電話番号が含まれるため、公開 URL・RSC payload で非提出権限者へ渡さない（管理者専用値は条件下でのみ計算する既存流儀）。
- **AI**: 開催地推定は Anthropic SDK（web に導入済み）で行い、失敗は握りつぶして空欄にする。モデル・プロンプトは技術計画で決める（軽量モデル想定）。docx 生成に AI は使わない。
- **docx**: 同梱テンプレ（クリーン版 .dotx）を純コードで埋めて .docx を出力する。ライブラリ選定（XML 直接操作か docx ライブラリか）は技術計画。生成物は DB（bytea）保存＋認可つき route の既存流儀。
- **LINE**: 既存の大会別 Bot グループ配信と textV2 メンション基盤を再利用し、「@副連絡責任者」のメンション対象は副連絡責任者フラグから解決する（`line-mention-targets` に1関数追加の想定）。
- **ゲスト**: 許可パスの追加は `guest-access` の一覧に閉じる。
- **技術的 Non-goals**: 個人 push、LibreOffice、ファイルシステム保存、公開トークン。
- **未解決の技術論点**（技術計画へ申し送り）: ①遠征単位のキー（開催日の変更に対する安定性）②docx 生成手段 ③AI モデルとプロンプト・失敗時のリトライ有無 ④確定状況の保存単位（グループ×人）と取込名簿からの導出の実装位置 ⑤経路入力ページの URL 設計と代理入力のパラメータ ⑥同梱テンプレのクリーン化手順（原本から個人情報欄を空にした dotx を生成して commit）。

## 7. 設計判断の根拠

- **フラグで認可する（副連絡責任者）**: 提出係は一般会員のことが多く、副管理者ロールを渡すと他の管理操作まで開くため。会計フラグ（認可に使わない）とは逆の設計で、コメントで区別する。
- **確定状況を手入力にする**: 確定名簿は添付なしのメールや手動フラグで成立することが多く、人ごとの確定／補欠がデータに無い。遠征届の対象者は「確定した人」に限る必要があるため、名簿を会へ流す時点で管理者が入れる。他機能への配線は別 PR（運用開始前なので不整合を許容）。
- **遠征単位＝連続開催日**: 遠征届は「一続きの外出」ごとに1枚が自然で、週をまたぐ大会は2枚になる。級では分けない（意義がない）。
- **出場行は保存せず導出**: 出欠の変更に追随し、入力者の手間を減らす。
- **開催地の AI 推定**: 会場名から都市名は機械的に取れないが、人が都度入れるのは負担。推定は補助で、必ず修正でき、失敗で止まらない。
- **団体代表者・留守連絡先をサークル長から導出**: 年度ごとに設定を書き換える手間を減らし、設定に残るのは顧問教員だけにする。
- **同梱テンプレをクリーン版にする**: 原本には団体代表者の電話など個人情報が入っており、git 履歴に残さない。届の値はデータから埋まるので運用上の不利益はない。
- **ダウンロードは提出権限者のみ・公開 URL なし**: 生成物に全員の電話番号が入るため。原本も同じ範囲に絞る（一般会員に用途が無い。デザイン収束 R3 で決定）。
- **行き・帰りを3択ずつにする**: 「帰省先から出場」だけでは「そのまま帰省」「学会先から向かう」が表現できず、備考の書き分け（出場のあと何も書かない／移動で表す）が本人の入力から機械的に決まるようにした（R2・R3）。
- **既定行は本人の出場日基準**: 記入例では自分の出場日の翌日に帰る人が多く、単位の最終日を基準にすると余計な滞在日が既定に入る（R2）。
