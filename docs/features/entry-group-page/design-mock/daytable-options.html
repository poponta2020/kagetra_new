長所 行の高さは案Aと同じ 38px のまま、大会名に 89px（約6文字）残る。ボード（要申込／抽選待ち／要振込／完了）と同じ語彙なので、 一覧と詳細で言葉が一致する。「今この日に何をすべきか」が朱で立つ。
短所 申込と支払の2軸が1語に潰れる（「申込済・未払」が「要振込」の一語になる）。 ボードの区画判定はグループ単位なので、日ごとに同じ判定を回す実装が要る。

3案に共通していること

  • 行の左端の チェックボックスだけが管理者に増える。一般会員は同じ行から選択枠が消えるだけで、列も情報量も変わらない（要件 AC-9）。
  • チェックボックスは行リンクの外に独立したタップ標的として置く。行の残り全体がその日の大会詳細（/events/[id]）へのリンク。
  • 「●」は自分がその日に参加すると答えた印。未回答は無印。管理者・一般会員とも同じ位置に出る。
  • 右端の人数は参加希望者数（attend=true の素通し・ゲストは数えない）。0名でも数字を出す。
  • 一括操作は日程表の直下。前進3種はボタン、後退3種は「戻す操作」に畳む（誤操作を1段遠ざける）。
  • フロー帯の「大会申込」は申し込まない日を除いた残りが全部揃ったら完了。多摩CDE は C だけが対象日で、それが申込済なので完了になっている。
