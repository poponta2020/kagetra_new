# annual-registration-renewal 要件定義書

年度替わりの全日協（一般社団法人全日本かるた協会）登録更新に向けて、前年度登録会員の「所属継続の有無」と「登録情報の変更有無」をアプリで確認・集計し、会 LINE グループの Bot で未回答者へリマインドする。あわせてサークル所属者の学年を年度替わりで更新する。

## 1. 概要

- **目的**: 毎年 3 月、登録会（北海道大学かるた会）が全日協へ提出する「継続者の届出・退会届・変更届」を作るために、管理者が個別に聞いて回っている「今年度も登録するか」「登録情報に変更はないか」の確認を、会員の自己申告＋アプリの集計に置き換える。該当会員の全員が答え終わったかが一目で分かる状態にする
- **背景**: 登録会規程 第8条により、登録会は年度当初に所属する正会員・准会員の氏名等を届け出て会費をまとめて納入する（会費は 4/30 まで）。実運用は「全日協から届く会員名簿（確認用・3/1 現在）」を基に、退会届（別表3）・変更届（別表2）を紙で作って 4 月初めに郵送し、その後の不備対応を経て 5 月頃に確定する。提出物の作成・郵送・会費振込は今後も人が行う（本機能は確認と集計まで）
- **同時に解決すること**: 学年（`users.school_year`）の年度繰り上げ。遠征届（travel-report）で「運用で更新」としていたものを、同じ年度確認の中で本人に確定させる

## 参考資料（全日協 会員ページ・2026-09-08 取得。原本は git 外）

- 定款 第6条: **正会員＝事業年度開始日の前日（3/31）までに満 20 歳に達している者、准会員＝達していない者**。賛助会員・名誉会員は別枠
- 登録会規程 第8条: 登録会は**年度当初に所属する正会員・准会員・賛助会員の氏名等を届け出**、届け出た会員の会費をまとめて納入する。年度途中入会は都度。第8条4項: 競技会の A/B/C 級出場者は正会員又は准会員でなければならない
- 会員規程 第5〜6条: 会費は正会員 10,000 円／准会員 5,000 円（5段以下の正会員は当分 5,000 円）、**毎年 4/30 まで**に登録会経由で納入。昇段と同時に入会する者は当該年度免除。第3条: 入会申込書の記載事項に変更が生じたら変更届（別表2）。住所・電話の変更を段位申請と同時に行う場合は不要
- 様式（各種届出様式）: 入会申込書（別表1）の項目＝氏名・ふりがな・生年月日・段位・出場級・指導者/支援者・性別・住所・会員区分（正/准/賛助）・備考（学生種別）／変更届（別表2）＝住所・電話番号・姓名の異動（変更前/変更後）／退会届（別表3）
- 通達「会員の移籍にかかわる届出運用ルール見直し」（2016）: 移籍は旧所属会から退会届＋新所属会から入会届

### 実際の年度更新の提出物（`docs/全日協登録/`・gitignore 済み・実名を含むため本書には転記しない）

- **全日協から届く「会員名簿（確認用）」**（PDF・3月1日現在・前年度分）: 正会員／准会員の区分ごとに、No・氏名・段位（漢数字）・出場級・性別・郵便番号・住所1・住所2・電話番号・ふりがな・生年月日・公認資格 の列。2025年度分は正会員 28 名＋准会員 3 名。管理者はこれに退会者を赤で印し、届出を作る
- **退会届（別表3）**: ふりがな・氏名・生年月日・段位・出場級・性別・会員区分。1枚 4 名まで（2026.3 は 2 枚・7 名）
- **変更届（別表2）**: 対象者の氏名・段位・出場級 ＋ 変更前／変更後（ふりがな・性別・郵便番号・住所・電話番号・備考「大学生」）。1 人 1 枚（2026.3 は 6 枚＝住所 5・電話 1）
- **入会申込書（別表1）**: 新規（今回のスコープ外）
- 会費は継続者分をまとめて振込（2026 年は 25 名 × 5,000 円）。届出日付は 4/2、名簿基準日は 3/1 ＝ **確認作業は 3 月に行う**

### LINE 送信方式の参照実装（match-tracker `line-chat-worker`）

- LINE Official Account Manager（OAM）の**チャット予約送信**を Playwright で登録する常駐ワーカー。OAM チャットは無料メッセージ通数の対象外（グループ push は人数分課金＝67 名グループなら 1 通で 67 通消費）
- Oracle VM（kagetra と同居）で docker compose 稼働中。アプリ API（`GET /api/line-chat-worker/tasks`・`POST /api/line-chat-worker/{id}/result`・`POST /api/line-chat-worker/session-warning`、`X-Service-Token` 認証）を 5 分間隔でポーリングし、`chatRoomId`（OAM 側 `C…`）・`chatRoomName`（OAM の見出しと完全一致）・`scheduledSendAt`（**10 分単位**・未来）・`messageText` のタスクを予約する。結果は `RESERVING → RESERVED / FAILED / MANUAL_REVIEW_REQUIRED / DRY_RUN_SUCCEEDED`、取消は `CANCEL_PENDING → CANCELLED`
- 24 時間セッションは自動再ログイン、**30 日 SSO は約月 1 回の手動ログイン**（失効 3 日前に管理者へ先回り警告）。storageState は **LINE Business ID 単位**で配下の全 OA に共通（実測済み）
- OAM チャットの入力欄は textarea（Enter 送信／Shift+Enter 改行）。**グループチャットで `@` によるメンションが使えることをユーザーが手動で確認済み**（2026-09-09）。候補ポップアップの DOM・照合キー（LINE の表示名と想定）・1 通あたりの上限は未調査＝実装前の PoC で確定する（R7・AC-31）。match-tracker のワーカーは本文のタイプしか実装しておらず、メンション操作は Page Object の追加になる

## 2. ユーザーストーリー

- **管理者（admin / vice_admin）**: 3 月に全日協から「会員名簿（確認用）」が届いたら、アプリで「年度確認」を開始（年度・回答締切を指定）する。前年度登録会員の全員が「継続の有無」と「登録情報の変更有無」を答え終わったかを一目で把握し、名簿の写し＋差分を見ながら退会届・変更届を紙で書く。提出後、不備のやり取りを経て登録が確定したら（5 月頃）「登録完了」を押す
- **会員（全日協登録者）**: LINE の案内リンクかホームの未回答バナーから自分の登録情報（名簿の列）を見て「継続・変更なし／継続・変更あり（その場で修正）／今年度は登録しない」を答える。未入力の項目（ふりがな・生年月日・住所など）はここで埋める
- **会員（サークル所属者）**: 同じ画面で「4 月からの学年」（+1 の既定値・最終学年は進学／卒業／留年の選択）を答える。全日協登録の有無とは独立
- **Bot（会 LINE グループ）**: 開始時の案内と、締切まで一定間隔の未回答者リマインドを流す。送信は Messaging API push（人数分課金）ではなく **OAM のチャット予約送信（Playwright 常駐ワーカー・match-tracker 方式）**

## 3. 機能要件

### 3.1 画面と遷移（見た目は design-spec 参照）

| ID | 画面 | パス（仮） | 権限 | 役割 |
|----|------|-----------|------|------|
| S1 | 年度確認（会員） | `/renewal` | ログイン会員本人（ゲスト不可） | 自分の登録情報の確認・修正、継続可否、来年度の学年の回答 |
| S2 | 年度確認 管理 | `/admin/members/renewal` | admin / vice_admin | 未開始: 開始フォーム／進行中: 集計ボード（名簿の写し）・代理回答・締切変更・登録完了／完了後: 直近の結果の閲覧 |
| S3 | 会 LINE グループ設定 | `/settings/club-line-group` | admin / vice_admin | プールから Bot を 1 体選び、OAM のルーム URL とグループ表示名を登録。直近の送信タスクの状態 |
| S4 | ホームの未回答バナー | `/dashboard` 内 | 対象会員 | 進行中の年度確認で自分に未回答セクションがあるとき、S1 への導線を出す |
| S5 | 会員編集（既存・改修） | `/admin/members/[id]/edit` | admin / vice_admin | 公認資格 2 項目（読手・準公認審判員）を追加 |

**遷移**
- 設定ハブ → S3。設定ハブの「会員」→ 会員一覧 → S2（一覧上部に「年度確認」導線）。S2 の各行 → S5（既存の会員編集）
- 会員: S4 → S1／LINE の案内文中の URL → S1。未ログインなら既存の認証フローで LINE ログイン後にホームへ戻るため、案内文に「ログイン後はホームの『登録確認』から開けます」を添える（ログイン後の戻り先指定は認証周りの変更になるため今回は行わない）
- S1 は回答後も同じ URL で再表示でき、「登録完了」まで修正できる

### 3.2 ビジネスルール

**R1. 対象者**
- 年度確認の対象は開始時点で `zen_nichikyo = true` ∧ `deactivated_at IS NULL` ∧ `role ≠ guest` の会員（＝全日協セクションの対象）。フラグのずれ（名簿と一致しない）は開始前に管理者が会員編集で直す
- 学年セクションの対象は開始時点で `is_circle_member = true` ∧ 未退会 ∧ ゲスト以外（全日協登録の有無と独立。両方に該当する会員は両セクション）
- 対象集合は**開始時点で確定**し、開始後にフラグを変えても対象は増減しない（Non-goal）。開始後に退会処理された対象者は集計から外し、ボードでは「退会」印で表示する
- 会員区分は保存しない。**正会員／准会員は生年月日から導出**する（対象年度の 4/1 の前日＝3/31 時点で満 20 歳なら正会員、それ以外は准会員。生年月日未入力なら「未判定」）。賛助会員は考慮しない

**R2. 年度確認の開始（管理者）**
- 入力: 対象年度（既定＝翌年度。3 月に開始するため）・回答締切（日付。今日より後）・任意の一言（案内文に添える自由文。200 字まで）
- 同時に進行できる年度確認は 1 つ。同一年度で 2 回開始することはできない（完了後もやり直し不可＝Non-goal）
- 開始時に対象者ごとに**スナップショット**（全日協セクション: 姓・名・姓かな・名かな・生年月日・性別・段位・級・郵便番号・住所1・住所2・電話／学年セクション: 学部区分・学部等名・学年）を保存する。差分表示の基準はこのスナップショット
- 開始の前提: S3 の会 LINE グループ設定が完了していること、`PUBLIC_BASE_URL` が設定されていること（S1 の絶対 URL を案内に載せるため）。満たさなければ開始できず理由を表示する
- 開始と同時に**案内文の送信タスク**を作る（R7）

**R3. 全日協セクションの回答（会員）**
- 表示: スナップショットではなく**現在の登録内容**を名簿の列順で表示し、未入力の項目は入力欄にする。正会員／准会員（導出値）と公認資格は読み取り専用で添える
- 選択肢は 2 つ: **「今年度も登録する」**／**「今年度は登録しない」**。「登録する」を選ぶには必須項目（姓名・ふりがな・生年月日・性別・級・郵便番号・住所1・電話。段位は A 級のみ必須＝既存規則）が全て埋まっていること。「登録しない」は項目が欠けていても選べる
- 「登録する」の画面では各項目をその場で修正できる。修正は `users` へ**直接保存**する（既存の会員編集と同じ形式検証。全日協 ON の必須条件も同じ）。**変更の有無は本人の宣言ではなく、スナップショットと現在値の差分から導出**する（管理者が年度中に会員編集で直した分も差分に出る）
- 回答は「登録完了」（R9）まで何度でも変更できる。回答者と回答日時を記録する（本人／管理者代理の区別つき）
- 対象外の会員（全日協 OFF・ゲスト）が S1 を開いた場合、全日協セクションは表示しない（学年セクションのみ、または「対象ではありません」）

**R4. 学年セクションの回答（サークル所属者）**
- 表示: 現在の学部区分・学部等名・学年と、**「4 月からの学年」**の選択。既定値は現在の学年を 1 つ進めたもの（`SCHOOL_YEAR_ORDER` の並びで 1 年→2 年、修士1年→修士2年 など）。現在の学年が未設定なら既定値なし
- 最終学年（学部: その学部等名の最終学年＝4 年、医・歯・獣医など 6 年制は 6 年／修士 2 年／博士 3 年／専門職 3 年）のときは既定値を置かず、**「進学」「卒業（サークルを離れる）」「留年（同じ学年）」**から選ぶ。「進学」は新しい学部区分（大学院）・学部等名（候補つき自由入力）・学年（修士1年／博士1年／専門職1年）を入力させる。最終学年以外でも「サークルを離れる」「学年を自分で選ぶ（留年・転学部など）」を選べる
- **反映タイミング**: 回答時点では `users` を書き換えず回答として保持し、**対象年度の 4/1（JST）以降に反映**する（日次バッチ。4/1 以降の回答は即時反映）。反映内容: 学年（＋進学なら学部区分・学部等名）／「卒業」は `is_circle_member = false`（学部等名・学年は残す）
- 反映後に本人が S1 で回答を変えた場合も、同じ規則で再反映する（4/1 以降なので即時）

**R5. 確認済みの定義と集計（管理者ボード）**
- **確認済み**＝全日協セクションの回答がある対象者。ボードの主集計「N / M 確認済み」は全日協セクションの対象者を母数にする。学年セクションは副集計「学年 回答 n / m」として別に出す
- 行の分類（絞り込みタブ）: **未回答**／**継続・変更なし**（登録する ∧ 差分なし）／**継続・変更あり**（登録する ∧ 差分あり。変更前→後を項目ごとに表示）／**登録しない**。名簿の写しとして各行に名簿の列（氏名・段位・級・性別・郵便番号・住所1・住所2・電話・ふりがな・生年月日・公認資格・正/准）を出す。行のメタ情報として LINE 紐付けの有無・リマインドに載った回数・回答日時と回答者（本人／管理者）を出す
- 進行中のヘッダーに「次のリマインド M/D 20:00」（R7 の日程規則から導出。残りが無ければ出さない）を表示する
- 出力（CSV・PDF 等）はしない。管理者はこの画面を見て紙に書く

**R6. 代理回答（管理者）**
- ボードの各行から、管理者が本人に代わって「登録する／登録しない」を記録できる（回答者＝管理者として記録）。登録情報の修正は既存の会員編集（S5）で行い、差分は同じ規則で導出される
- LINE 未紐付けでログインできない対象者（`line_user_id IS NULL`）はこの経路で処理する

**R7. LINE 送信（会グループ・OAM チャット予約送信）**
- **案内（開始時）**: 開始直後の送信タスクを 1 件作る。送信予定時刻＝現在時刻＋15 分を 10 分境界へ切り上げ。本文＝固定テンプレ（対象年度・締切 `M/D(曜)`・S1 の絶対 URL）＋管理者の一言
- **リマインド**: 対象日の 19:30（JST）の日次バッチが、その時点の**全日協セクション未回答者**を集計し、0 人でなければ同日 20:00 の送信タスクを作る。対象日＝開始日の 3 日後から 3 日おき（開始日 +3, +6, …）・締切前日・締切当日（重なる日は 1 件）。締切を過ぎた日は作らない。本文＝固定テンプレ（締切・**未回答者へのメンション**・S1 の URL）
- **メンションの解決**: 未回答者ごとに、転換した Bot の「グループメンバープロフィール取得」API（`GET /v2/bot/group/{groupId}/member/{userId}`。既存 `line-group-membership` と同じ API）で **LINE の表示名**を引き、タスクに「メンション対象＝表示名の配列」として持たせる。ワーカーは OAM の入力欄で `@` を打って候補から表示名一致のメンバーを選ぶ。表示名が引けない（LINE 未紐付け・グループ未在籍・API 失敗）／候補が一致しない人は**メンションせず氏名をテキストで列挙**する（フォールバック。リマインド自体は必ず送る）
- **分割**: OAM 側の 1 通あたりのメンション上限（PoC で確定）を超える人数は、20:00・20:10・20:20… と 10 分ずつずらした複数タスクに分ける（ワーカーの重複検出が「同一日時」で弾くため同時刻に複数は置けない）。各タスクの本文は同じテンプレで、メンション対象だけ分ける
- **PoC ゲート（AC-31）**: メンション操作の実 DOM（候補ポップアップの出し方・選択・確定後の本文表現・上限）は、match-tracker と同じくテストグループでの PoC で確定してから本番に入れる。PoC が不成立なら全員テキスト列挙（上のフォールバック）で出荷し、メンションは別 Issue へ送る
- 学年セクションだけが未回答の会員はリマインドに載せない（会グループにいるのは登録会員全員という前提であり、サークル員全員ではないため。学年は S4 のバナーで促す）
- 同一日に同種のタスクを二重に作らない（(年度確認, 種別, 送信日時) で一意）
- タスクの状態（予約済み・失敗・要確認）は S2・S3 に表示する。**失敗・要確認・SSO 失効の先回り警告は既存の管理者個人 LINE（system_notify チャネル）へ通知**する。push によるフォールバック送信はしない（管理者が手で投稿する）
- 締切変更（R8）や登録完了（R9）で不要になった未送信タスクは取消（`CANCEL_PENDING`）にする

**R8. 締切の変更**
- 進行中は締切を変更できる（今日以降の日付）。以後のリマインド日程は新しい締切で計算する。送信済みの案内は取り消さない

**R9. 登録完了（管理者）**
- 「登録完了」を押すと: (1)「登録しない」と回答した対象者の `zen_nichikyo` を `false` にする、(2) 年度確認を完了状態にする（以後 S1 は閲覧のみ・S4 のバナーは消える）、(3) 未送信の送信タスクを取り消す
- 未回答者が残っていても実行できる（確認ダイアログに未回答の人数と氏名を出す）。未回答者のフラグは変えない（＝継続扱い）
- 完了は取り消せない（フラグの巻き戻しは会員編集で個別に行う）

**R10. 会 LINE グループ設定（S3）**
- プールの Bot（`line_channels`・`available`）から 1 体を選ぶ。選んだ Bot は大会・級別の配信に使われないよう専用の用途に転換する（元に戻す操作も置く）
- OAM でそのグループを開いたときの URL（`https://chat.line.biz/<U…>/chat/<C…>`）とグループ表示名（OAM の見出しと完全一致）を登録する。URL からアカウントパスとルーム ID を取り出して保存し、形式が違えば拒否する
- 手順の案内を画面に置く: Bot をグループに招待 → 誰かが一言発言 → OAM にルームが現れる → URL をコピー。Bot が招待されたときの webhook（join）で **webhook 側のグループ ID（`C…`。OAM 側の `C…` とは別の値）を捕捉して保存**する（メンション解決の表示名取得に使う）。グループ内の発言は無視する。捕捉できていない間はメンション解決ができず、リマインドはテキスト列挙になる（S3 に捕捉状態を表示）
- 送信タスクの直近の状態（種別・送信予定・状態・エラー）を一覧で見せる。失敗したタスクの再試行（送信予定が未来の場合のみ）を置く

**R11. 公認資格（users 追加）**
- 読手: なし／B 級公認／A 級公認。準公認審判員: 有無。管理者が S5 で編集。S1 では読み取り専用、S2 の名簿の写しに表示

**R12. 権限**
- S1 は本人のみ（他人の回答・情報は URL を変えても見えない）。ゲストは対象外
- S2・S3・開始・締切変更・代理回答・登録完了・Bot 転換は admin / vice_admin
- ワーカー API（`/api/line-chat-worker/**`）はサービストークンのみ（セッション不可・トークン無し 401／不正 403）。既存のセッション認可エンドポイントにサービストークンでは入れない

**R13. エラー・境界**
- 開始条件未達（LINE 未設定・`PUBLIC_BASE_URL` 未設定・進行中あり・同年度実施済み）は開始を拒否し理由を表示
- スナップショット保存と案内タスク作成は 1 トランザクション（途中失敗で「開始したのに案内が無い」状態を作らない）
- 送信タスクの本文は生成時に確定（送信時に再計算しない）。予約は 10 分境界・未来時刻のみ
- リマインド日にワーカーが止まっていて予約できなかった場合、その日の分は送られない（翌対象日に改めて集計）。失敗は管理者へ通知
- 対象者が回答前に退会処理された場合はボードで「退会」印・集計から除外。リマインドの列挙からも外す

## 6. 技術的制約・契約

- **互換性**: 会員編集（`updateMemberProfile`）・招待リンク登録・遠征届（`school_year` の意味・`SCHOOL_YEAR_ORDER`・S8 の「あなたの情報」）・大会別／級別 LINE 配信・Bot プール・webhook（`purpose` による振り分け）は現行どおり動くこと（AC-26・AC-29）。`users.name`（合成表示名・UNIQUE）の扱いは既存の会員編集と同じ規則に従う
- **公開契約（ワーカー）**: match-tracker `line-chat-worker` の `WorkerTask` / `ResultReportBody` / `session-warning` の形を基本にし、**メンション対象（LINE 表示名の配列）を後方互換の追加項目**として載せる（項目が無ければ従来どおり本文タイプのみ＝match-tracker のタスクは影響を受けない）（AC-22）。kagetra 側のエンドポイントは `/api/line-chat-worker/tasks`・`/api/line-chat-worker/{id}/result`・`/api/line-chat-worker/session-warning`、認証は `X-Service-Token`（kagetra 専用の env・match-tracker のトークンと共有しない）。middleware の matcher から除外し、route 内でトークン検証する（`/api/external/**` と同じ流儀）
- **クロスリポジトリ依存**: match-tracker の `line-chat-worker` に「複数アプリ（URL・トークン・OA アカウントパス）をポーリングする」拡張と「`@` 候補からのメンション選択」の Page Object 追加が必要（別リポジトリの PR＋VM の `.env` 更新＋再起動。メンション部分は PoC ゲート付き）。storageState（LINE Business ID 単位）は共有され、月 1 回の手動ログインは増えない。kagetra 側は拡張がデプロイされるまでタスクが `PENDING` のまま残るだけで壊れない
- **保持データ・移行**: 新テーブル（年度確認・対象者スナップショット＋回答・送信タスク・会 LINE グループ設定）と `users` への公認資格 2 列、`line_channels.purpose` の値追加を Drizzle migration で追加する（本番は CI の deploy が自動適用）。既存行への影響なし
- **セキュリティ・権限**: スナップショットは住所・電話・生年月日を含む PII なので `users` と同じ扱い（S1 は本人・S2 は admin/vice_admin・RSC payload で他人へ渡さない）。LINE へ出すのは氏名のみ。サービストークン・OAM の URL はログに出さない
- **定期実行**: 19:30 のリマインド集計と 4/1 以降の学年反映は systemd timer（既存の `kagetra-*.timer` と同じ配置・`auto-deploy.sh` が自動配置）。冪等（同日再実行で二重作成しない）
- **時刻**: 送信予定時刻は JST・10 分境界・未来。日付判定は JST（既存 `jst-date`）
- **技術的 Non-goals**: Messaging API push 経路の新設、ワーカーの kagetra への移植、OAM の DOM 操作コードを kagetra に持つこと
- **技術論点の確定**: 以下①〜⑩は 2026-09-09 の技術計画（`implementation-plan.md` の「技術設計（確定）」）で解決済み。JSONB スナップショット（型付き・zod）／タスクの部分 UNIQUE（CANCELLED 除外）と日単位の冪等／新規 timer 2 本（19:30・00:05）と学年回答の絶対値保存／`name` 不変／ワーカー契約は固有項目を返さず `mentions` を後方互換で追加／`purpose='club_chat'`＋CAS 転換／6 年制学部の一覧は共有定数／ログイン後の戻り先は案内文で代替／メンション上限は設定値（PoC 後に確定）／表示名取得は既存プローブと同経路
- **（記録）当初の未解決論点**: ①スナップショットの保存形（JSON 1 列か項目別列か）と差分計算の置き場所 ②S1 の氏名修正時に `users.name` を再合成するか（既存 S8・会員編集の規則の確認） ③19:30 バッチ・4/1 反映を新規 timer にするか既存 `lifecycle-reminders`（00:00）へ相乗りするか ④転換した Bot の表現（`purpose` 新値＋`status`）と webhook の join 捕捉／発言無視の経路 ⑤ワーカーの複数アプリ設定の形（env JSON 等）と per-app dry-run の要否 ⑥`WorkerTask` の match-tracker 固有項目（`broadcastGroupId`・`sessionId`）の扱いとメンション項目の形 ⑦最終学年の判定（6 年制学部の一覧をどこに持つか） ⑧S1 の URL とログイン後の戻り先 ⑨メンションの 1 通あたり上限の設定値の置き場所（PoC 後に確定）と、分割タスク間で本文を揃える方法 ⑩表示名取得 API のレート・所要時間（数十人分を 19:30 バッチ内で直列に呼ぶ）

## 7. 設計判断の根拠

- **OAM チャット予約送信を採用**: グループ push は人数分課金（67 名なら 1 通＝67 通）で無料枠 200 通/月では月 2 回しか送れない。match-tracker が同じ制約を OAM チャット（通数対象外）で回避し本番運用中のため、その資産とセッション（Business ID 共通）を再利用する。ワーカーは移植せず複数アプリ対応にするのは、storageState の月 1 回手動ログインを 2 回に増やさないため
- **メンションは PoC ゲート付きで採用、フォールバックはテキスト列挙**: OAM のグループチャットで `@` メンションが使えることは手動で確認できたが、自動操作の実 DOM・照合キー・上限は未調査。match-tracker と同じ段階ゲートで不確実性を切り離し、不成立でもリマインド自体（テキスト列挙）は必ず出荷できる形にする。照合は LINE 表示名（Bot の API で取得）で行い、一致しない人はテキストに落とす（ユーザー判断・2026-09-09）
- **変更有無を差分から導出**: 本人の「変更なし」宣言と実データの食い違い（年度中の会員編集）を管理者が見落とさないため。紙の変更届は「変更前／変更後」なので差分そのものが必要
- **会員区分を導出**: 定款の定義（3/31 時点で 20 歳）が機械的で、保存すると毎年更新が要る
- **学年は 4/1 に自動反映、全日協 OFF は登録完了ボタン**: 3 月の回答を即時反映すると 3 月の遠征届に来年度の学年が載る。一方で全日協の確定は不備対応を経て 5 月にずれるので、同じボタンに束ねると 4〜5 月の遠征届が旧学年になる
- **対象集合を開始時に固定**: 「該当する前年度登録会員の全員が確認を終えたか」を判定するには母数が動かないことが前提。名簿（3/1 現在）に合わせて開始前にフラグを整える運用
- **登録完了を未回答ありでも許可**: 管理者が電話等で把握した人を代理回答で埋められるため、未回答が残るのは「管理者が継続と判断した」場合に限られる。ブロックすると完了できない
- **LINE リマインドは全日協未回答者だけ**: 会グループの在籍前提は「登録会員全員」であり、サークル員全員ではない。学年だけの人を名指ししても届かない可能性がある
