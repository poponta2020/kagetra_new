# 大会申込（イベント一覧）改善 デザイン仕様（design-spec）

> `/design-screen` の確定仕様。ロジック（締切ルール・ソート・申込可能判定・参加者集計）は
> [`requirements.md`](./requirements.md)（status: completed）が正。ここは**見た目の確定形**。
> 確定モック: Claude Design `イベント一覧 (Redesign)` グループ / `preview/event-list-refinements-b.html`（ユーザー編集反映済み）。

## 1. 対象と狙い
- **対象画面:** `/events`（見出しを「大会申込」に）。過去一覧・詳細は非対象。
- **不満:** 開催日と締切日が同体裁で2行並びわかりづらい／会場・公認ピルがノイズ／開催日固定順のみ。
- **狙い:** 「いつの大会か・いつまでに申込むか・誰が出るか」を1行で。締切順が既定、申込可能で絞れる。

## 2. 採用した方向性
- **B案 — ラベル付きメタ型 × 区切り線リスト。** 開催日をタイトル同行に置き、締切はカウントダウンを右端に。カード枠をやめ**行間ボーダーのリスト**に（情報密度優先）。
- **不採用:** A案（日付リード・左に大きな日付ブロック）＝ boxed card で1件が縦に大きく、件数が増えると冗長。B案の方が一覧性が高い。
- 参加者は苗字チップ＋「他N名」（既存 `card-event` コンポーネントの作法を踏襲）。

## 3. レイアウト構成（上→下）
1. **外殻（既存 MobileShell）:** `かげとら` ワードマーク＋`{名前}さん`。変更なし。
2. **見出し行:** `h1「大会申込」`（明朝）＋右に「過去のイベント →」リンク・（管理者のみ）「新規作成」ボタン。※文言以外は現状踏襲。
3. **コントロール行（新規・見出し直下）:** 左＝セグメント「開催日順 / 締切日順」（活性=brand 塗り・白字／既定=**締切日順**）。右＝「申込可能のみ」ラベル＋スイッチ（既定 OFF・ON で brand track）。
4. **イベントリスト（区切り線）:** カード枠なし。各行 `padding:13px 2px`、行間に `1px solid border-soft`。各行＝
   - **上段（baseline 揃え）:** `M/D(曜)`（明朝・太）｜ 大会名 `title`（18px 太・可変幅で省略）｜ （中止/終了なら status ピル）｜ 右端に締切カウントダウン。
   - **下段:** 「参加 {N}名」小ラベル＋苗字チップ最大5＋「他{N−5}名」。

## 4. 使用コンポーネント
- **既存:** GradePill（※一覧の苗字チップには級ピルは付けない）／StatusPill（中止=danger・終了=info。published は非表示）。参加者チップは `card-event` の苗字チップ様式（`bg-neutral-bg` 系 pill）。
- **新規（一覧固有）:**
  - **区切り線リスト行**（カード枠を使わない一覧行）。
  - **締切カウントダウン**：`締切` ラベル＋値。tone で色/太さ/サイズを出し分け（下表）。
  - **並び替えセグメント**（2軸・pill 容器）＋ **申込可能スイッチ**（トグル）。

## 5. 状態（state）
- **通常:** 上段＝日付/大会名/締切、下段＝参加者チップ。
- **締切カウントダウン tone:**
  | tone | 条件 | 文言 | スタイル |
  |---|---|---|---|
  | today | 当日 | `本日` | 朱（accent-fg）・太字・やや大 |
  | soon | 1〜3日 | `あとN日` | 黒字・太字・数字大 |
  | normal | 4日以上 | `あとN日` | ink-2・通常 |
  | past | 超過 | `締切済` | ink-muted（淡色） |
  | none | 締切なし | `—` | ink-muted（ラベル「締切」＋ダッシュ・行は残す） |
- **中止:** タイトル淡色（ink-meta）＋`中止`ピル（danger）。締切カウントダウンはそのまま表示。
- **参加者0名:** 下段の「参加 0名」のみ（チップなし）。※実装で 0 名時のチップ行の出し方は軽微裁量。
- **長いタイトル:** 省略（…）。日付・締切は固定幅側なので潰れない。
- **申込可能フィルタ ON で 0 件:** 空表示（文言例「申込可能な大会はありません」）。
- **全体 0 件（未来イベント無し）:** 現状の空表示（「現在のイベントはありません」）を踏襲。

## 6. 必要データ
- **表示:** `title` / `eventDate`（→ `M/D(曜)`）/ `internalDeadline`（→ カウントダウン）/ `status`（→ ピル）/ 参加者名 `users.name`（→ `surname()`）/ 参加数 `N`。
- **導出:** 締切残日数＝`internalDeadline − 今日(JST)`。曜日＝`eventDate` から。`canApply`＝`isGradeEligible(eligibleGrades, myGrade)`（サーバー算出）。
- **参加者:** `attend=true` を `users` 結合で取得→イベント別に級昇順→先頭5名の苗字＋総数。**1 クエリで表示中イベントぶんまとめて取得**（N+1 回避）。詳細は requirements 4.3。

## 7. インタラクション / レスポンシブ
- **操作:** 並び替えセグメント切替（クライアント state・既定=締切日順）／申込可能スイッチ（クライアント state・既定 OFF）／行タップで `/events/[id]`。状態は画面内のみ（永続化しない）。
- **モバイル 375px:** 上段は `日付＋締切` を固定幅・`title` を可変幅（`flex:1`＋省略）で横スクロールを避ける。チップは折返し可。

## 8. ガードレール準拠メモ
- washi×藍墨・二値セマンティック維持。**朱は「本日締切」＝締切の許容用途**でのみ使用（データ装飾ではない）。級・種別を虹色にしない。
- 明朝＝日付の数字・見出し・大会名。絵文字なし。日付は `M/D(曜)`（②の明示要望・ゼロ埋めなし）。

## 9. 残課題・実装への申し送り
- 参加者チップの並びは詳細画面（級昇順・未設定末尾）に揃える。表示上限5は helper 定数。
- 締切「3日以内」しきい値＝3（helper 定数）。tone→クラスの対応は上表。
- 見出しは `h1` のみ「大会申込」。ボトムナビのタブ名「イベント」は据え置き（別スコープ）。
- 参加数の集計は現行 `attend=true`（詳細画面の eligible 絞り込みとは別・一覧は数の一貫性を優先）。

## 10. 要件への宿題（→ /define-feature event-list-refinements）
- なし（emergent logic＝既定ソート/日付曜日/締切3段階/参加者チップ/見出し改称 は requirements へ反映済み・収束）。
