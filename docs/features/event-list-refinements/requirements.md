> 過去イベント一覧（`/events-archive`）・イベント詳細（`/events/[id]`）は**現状維持（今回は触らない）**。

## 1. 概要

### 目的
イベント一覧カードの情報を整理し、会員が「いつの大会か・いつまでに返事すべきか」を一目で判断でき、
並び替えで目的のイベントを探せるようにする。

### 背景・動機
現状カードは `title`＋`公認`ピル＋`開催日(YYYY-MM-DD)`＋`会場`＋`締切: 日付` を縦に積んでおり、
- 開催日と締切日が**同じ体裁の日付で2行並び**、どちらがどちらか分かりづらい（③）
- 会場・公認バッジは一覧では優先度が低くノイズ（①⑤）
- 開催日固定順のみで、締切の近いイベントを探しにくい（④）

## 2. ユーザーストーリー

- **対象ユーザー:** 一般会員（主）／管理者・副管理者（同じ一覧を見る）
- **目的:** これから参加できるイベントを一覧で素早く把握し、締切までの猶予を掴み、開催日／締切で並べ替えて探す
- **利用シナリオ:** 会員がトップから `/events` を開く → カードで「大会略称＋級・開催日(MM/DD)・締切まであとN日・参加人数・ステータス」を確認 → 「締切日順」に切替えて締切が迫ったものを優先確認 → 必要なら「申込可能な大会のみ」に絞り、自分の級で出られる大会だけ表示 → カードをタップして詳細で返答

## 3. 機能要件

### 3.1 画面仕様（`/events` 一覧カード）

対象6点の差分（視覚レイアウトの詳細は design-spec.md に委譲。ここでは表示ルール＝ロジックを定義）:

| # | 要望 | 変更内容 |
|---|------|----------|
| ① | 会場はいらない | カードから `location`（会場）の行を**削除**（表示のみ。DB 値は保持） |
| ② | 日付表記 | 開催日を `YYYY-MM-DD` → **`M/D(曜)`**（曜日付き・ゼロ埋めしない、例 `7/12(日)`）で表示 |
| ③ | 締切を「あと何日」 | 締切を**日付ではなく残日数**で表示（下記ルール・3段階強調）。開催日と体裁を分ける |
| ④ | 開催日・締切日でソート | 「開催日順 / 締切日順」の**2軸トグル**（昇順固定）。**既定＝締切日順** |
| ⑤ | 公認バッジはいらない | `公認` ピルを**削除**（表示のみ。`official` 値は保持） |
| ⑥ | 略称＋開催級 | 一覧タイトルは従来どおり **`title` を表示**（AI取込は既に「大阪ABC」等の略称＋級／手動作成は入力値）。**正式名称(`formalName`)は一覧に出さない＝現状どおり**。表示ロジックの変更なし |
| ⑦ | 申込可能な大会のみ絞込 | 「自分の級で出られる大会だけ」に絞るトグル。**デフォルトOFF**（＝全件表示）。**級だけで判定**（締切・中止は見ない） |
| ⑧ | 参加者チップ | 「参加 N名」の数字に加え、**参加者の苗字チップ**を先頭数名＋「他N名」で表示（詳細画面と同じ `surname()` 流用）。※design-screen 編集で追加 |
| 見出し | 大会申込 | ページ見出し `h1` を「イベント一覧」→**「大会申込」**に。ボトムナビのタブ名「イベント」は**据え置き**（変更は別スコープ） |

#### ② 日付表記ルール
- 開催日を `M/D(曜)` で表示（例 `7/12(日)`）。**ゼロ埋めしない**（`7/12` であって `07/12` ではない）。
- **曜日**は `eventDate` から算出（JST。`日月火水木金土`）。カッコは半角 `()`。
- 明朝（display フォント）で数字を組む＝design-spec 準拠。

#### ③ 締切表示ルール（基準＝会内締切 `internalDeadline`、JST 今日基準・3段階強調）
残日数 `daysLeft = internalDeadline − 今日(JST)`（日単位）で分岐:

| 条件 | 表示 | 強調（design-spec） |
|------|------|------|
| `daysLeft > 3` | 「あと{daysLeft}日」 | 通常（ink-2） |
| `1 ≤ daysLeft ≤ 3` | 「あと{daysLeft}日」 | **強調**（黒字・太字・数字大） |
| `daysLeft === 0`（当日） | 「本日」 | **朱で強調**（accent＝「締切」はガードレール許容用途） |
| `daysLeft < 0`（超過） | 「締切済」 | 淡色（ink-muted） |
| `internalDeadline === null` | **「—」** | 淡色（ラベル「締切」＋ダッシュ。行は残す） |

- 基準は**会内締切 `internalDeadline`**（現状カードに出ていた締切と同一。会員が返答すべき締切）。申込締切 `entryDeadline` は使わない。
- 「あと何日」の基準日は **JST の今日**。日付差のみで計算（時刻は持たない＝`date` 型）。
- 3日以内強調のしきい値 `3` は helper 内の定数。ラベルは常に「締切」を前置。
- **変更点（当初→編集後）:** 「あと何日」の3段階強調を追加。締切なしは「行を出さない」→「`—` ダッシュ表示」に変更（B案の同行レイアウトで欄を揃えるため）。

#### ④ ソート仕様
- トグルは **2軸: 「開催日順」「締切日順」**、**昇順固定**（降順・軸以外の切替は無し）。
- **既定＝締切日順**（design-screen 編集で確定。「いつまでに申込むか」を優先する画面意図に合わせる）。
- **締切日順:** `internalDeadline` 昇順（締切が近い順）。**`internalDeadline === null` のイベントは末尾**にまとめ、その中は `eventDate` 昇順を副キーとする。
- **開催日順:** `eventDate` 昇順（近い順）。同日は既存どおり id 等の安定順。
- ソート状態は画面内のみ（永続化・URL 反映はしない）。ページ再訪で既定（締切日順）に戻る。

#### ⑧ 参加者チップ仕様
- カード下段に **参加者の苗字チップ** を表示。「参加 {N}名」の小ラベル＋**先頭最大5名の苗字チップ**＋残りがあれば「他{N−5}名」。
- 苗字は詳細画面と同じ `surname(name)`（表示名 `users.name` を先頭空白で分割）。空白の無い名は名前全体を表示（`?` フォールバックも同一）。
- **チップの並び・母集合**は詳細画面の参加者表示に合わせる：`attend=true` の参加者を**級昇順（未設定は末尾）**で並べ、先頭5名を採用。件数 `N` は現行「参加 N名」と同じ `attend=true` 件数（＝一覧の集計セマンティクスは不変。名前を足すだけ）。
- チップ内に級ピルは**出さない**（一覧は密度優先。詳細画面は級ピル併記だが一覧では苗字のみ）。
- **データ影響:** 現行の一覧は参加「数」のみ集計。⑧のため**表示中イベントの参加者名も取得**する必要がある（4.3 参照）。

#### ⑦ 申込可能フィルタ仕様
- 「申込可能な大会のみ」を表す **ON/OFF トグル**。**デフォルト OFF**（＝現状どおり全件表示）。
- 判定は **級のみ**（`isGradeEligible`）:
  `対象級(eligibleGrades) が未設定` **または** `自分の級が対象級に含まれる` → 申込可能。
  **締切超過・中止(status)は考慮しない**（過去締切・中止の大会も自分の級向けなら残す）。
- **管理者バイパスはしない。** 管理者・副管理者も「自分の級」で判定する（＝管理者でもフィルタが実際に効く）。
- **自分の級が未設定（grade=null）の場合:** 対象級が設定されたイベントはすべて非該当となり、
  `対象級 未設定` のイベントのみが残る（＝級が無いと絞れる大会は限定的）。仕様どおりの挙動として許容。
- ソートとは独立に併用可（例: 申込可能ON × 締切日順）。フィルタ状態も画面内のみ（永続化しない）。
- ON の結果が 0 件なら空表示（例: 「申込可能なイベントはありません」）。

### 3.2 ビジネスルール
- 一覧に載る対象範囲は現状どおり **`eventDate >= 今日(JST)` の未来イベント**（変更なし）。過去は `/events-archive`。
- カードのタップ遷移先・参加人数集計・ステータスピル（`StatusPill`）は**現状維持**。
- 管理者のみ表示の「新規作成」導線、「過去のイベント →」リンクは**現状維持**。
- ①⑤で消すのは**一覧の表示のみ**。会場・公認の値は DB に残り、詳細画面（`/events/[id]`）では従来どおり表示。

## 4. 技術設計

### 4.1 API設計
- **新規/変更なし。** 一覧はサーバーコンポーネントが `db` から直接取得（現状どおり）。エンドポイント追加なし。

### 4.2 DB設計
- **スキーマ変更なし・マイグレーションなし。** `events.location` / `events.official` / `events.internalDeadline` は既存列をそのまま使用（①⑤は表示削除のみ）。

### 4.3 フロントエンド設計
現状 `page.tsx` は単一のサーバーコンポーネント。④ソートはクライアント操作なので、**データ取得（サーバー）と一覧描画＋ソート（クライアント）を分離**する。

- **`apps/web/src/app/(app)/events/page.tsx`（サーバー・改修）**
  - イベント一覧取得は現状ロジックを維持。加えて **一覧に `eligibleGrades` を含める**（⑦判定用）。
  - 見出し `h1` を **「大会申込」** に変更（ナビは据え置き）。
  - JST の今日 `todayStr` を算出（既存）。
  - **ログイン中ユーザーの `grade` を DB から取得**（⑦判定用。現状 `/events` では未取得なので追加）。
  - 各イベントの **`canApply`（＝`isGradeEligible(eligibleGrades, myGrade)`）をサーバーで算出**し boolean をカードデータに含める（クライアントは boolean で絞るだけ＝grade を渡さず済む）。
  - **⑧ 参加者名の取得（現行の count 集計を置換 or 併設）:** 表示中イベント（`visibleEventIds`）の `attend=true` 参加者を `users`（`name, grade`）と結合して取得し、JS でイベント別にまとめる。各イベント＝件数 `N`（現「参加 N名」と同値）＋**級昇順で先頭5名の苗字**（`surname(name)`）を算出して渡す。件数だけの現行グループ集計は名前取得で代替可能（件数＝行数）。**N+1 回避**のため 1 クエリ（`inArray(eventId, visibleIds)`）でまとめて取得。
  - シリアライズ可能な最小データ（`id, title, eventDate, internalDeadline, status, canApply, attendCount, chipSurnames: string[]`）＋ `todayStr` を新クライアント一覧コンポーネントへ渡す。`location`/`official`/`eligibleGrades`/`grade` は**カードに直接は渡さない**（①⑤・⑦は canApply へ畳む）。
- **新規クライアントコンポーネント（例 `EventListClient.tsx`, `'use client'`）**
  - ソート軸 state（`'deadline' | 'date'`、**既定 `'deadline'`**）＋ 申込可能フィルタ state（`boolean`、既定 `false`）とトグル UI（セグメント＋スイッチ）。
  - 渡された配列を「フィルタ → ソート」して**区切り線リスト**で描画（B案＝カード枠なし・行間ボーダー）。フィルタ ON なら `canApply === true` のみ。
  - 開催日 `M/D(曜)`・締切カウントダウンは下記 pure helper で算出（`todayStr` を prop で受け、`Date.now()` を描画時に呼ばない＝hydration mismatch 回避）。
  - フィルタ ON で 0 件のときの空表示を出し分け。
- **pure helper（テスト先行対象）**
  - `formatEventDate(eventDate: string): string` — `YYYY-MM-DD` → `M/D(曜)`（ゼロ埋めなし・曜日付き）。
  - `formatDeadlineCountdown(internalDeadline: string | null, todayStr: string): { text: string; tone: 'normal' | 'soon' | 'today' | 'past' | 'none' }` — ③の3段階ルール（あとN日/本日/締切済/—）。null でも `{ text: '—', tone: 'none' }` を返す（行は出す）。
  - `isGradeEligible(eligibleGrades: Grade[] | null, grade: Grade | null): boolean` — ⑦のルール（対象級未設定=true／自分の級が含まれる=true／grade=null かつ対象級ありは false）。
  - `surname(name)` — 既存の詳細画面のロジックを共有ヘルパー化（`apps/web/src/lib/` へ）して一覧・詳細で再利用。
  - `sortEvents(list, axis)` — ④のルール（締切軸は null 末尾＋eventDate 副キー／開催日軸は eventDate 昇順）。
  - 配置先は `apps/web/src/app/(app)/events/` 配下（例 `event-list-utils.ts`）または既存の日付/utility 置き場に合わせる。

### 4.4 バックエンド設計
- **変更なし**（サーバーアクション・worker・API いずれも非対象）。

## 6. 設計判断の根拠
- **③ 基準を会内締切にした理由:** 会員が「返答すべき」締切であり、現行カードにも出ていた締切と同一。申込締切（対主催者）は会員の行動締切ではないため一覧では使わない。
- **④ クライアント分離の理由:** ソートはページ内インタラクション。永続化不要のためサーバー再取得ではなくクライアント state で切替（軽量・小規模リスト）。
- **② 日付を一覧のみ `M/D(曜)` にする理由:** 一覧は未来イベント中心で年が自明。曜日は申込判断に有用（design-screen 編集で追加）。過去（複数年にまたがる）アーカイブは年が必要なので**今回は対象外**として現状維持。
- **④ 既定を締切日順にした理由:** 見出しを「大会申込」に寄せた通り、この画面の主目的は「締切までに申込む」こと。締切が近い順が既定だと行動が漏れにくい（design-screen 編集で確定）。
- **⑧ 参加者チップの理由・データ:** 誰が出るかが一覧で分かると申込判断が早い。詳細画面の `surname()` を流用でき実装・見た目が一貫。姓のみの `familyName` は既存会員で NULL のため使わず、表示名 `name` を空白分割する既存ロジックに揃える。件数集計は不変で名前取得を足すだけ（1 クエリ・N+1 回避）。
- **見出し「大会申込」の留意点:** `/events` は大会以外のイベントも入り得るが、運用実態が大会申込中心のためユーザー確定で改称。ボトムナビのタブ名「イベント」は据え置き（ナビ＋テスト＋design.md への波及回避＝別スコープ）。
- **⑥ title 据え置きの理由:** `title` は AI 取込で既に略称＋級、手動作成は入力運用でカバー。一覧は元々 `formalName` を出しておらず、要望（略称＋級／正式名称は出さない）は現状で満たされている。新たな級合成ロジックは作らない（スコープを増やさない）。
- **⑦ 級のみ判定・管理者バイパスなしの理由:** フィルタの意図は「選手として自分が出られる大会か」。詳細画面の `canRespond` は管理者を全許可バイパスするため、管理者が使うと全件残りフィルタが無意味になる。よって権限バイパスを外し「自分の級」で判定。締切・中止を除外しないのはユーザー指定（過去締切・中止でも“自分の級向け”として一覧に残す）。判定は詳細画面と共有の純関数 `isGradeEligible` に切り出し、対象級の解釈（未設定=全級）を一元化。
- **①⑤ を表示削除に留める理由:** 会場・公認は詳細では有用な情報。DB 値・詳細表示を残すことで可逆かつ他機能非破壊。

## デザインへの宿題（→ /design-screen event-list-refinements）— ✅ 解決済み（round 2・B案 locked）
下記の視覚論点は [`design-spec.md`](./design-spec.md)（status: locked, chosen_direction: B）で確定。宿題ゼロ＝収束ゲート通過。
- カード内レイアウト → **区切り線リスト**（カード枠なし）：`M/D(曜) 大会名 [締切カウントダウン]` を同行、下段に参加者チップ。会場行・公認ピル撤去。
- 締切の見せ方 → **3段階強調**（本日=朱／3日以内=黒太字・数字大／通常／締切済=淡）。朱は「締切」＝ガードレール許容用途で使用。
- コントロール → 見出し行の下に独立行：左＝並び替えセグメント「開催日順/締切日順」（既定=締切日順）、右＝「申込可能のみ」スイッチ（既定OFF）。
- 空表示（⑦フィルタ ON で 0 件）の文言・見せ方は design-spec の状態欄に記載。
