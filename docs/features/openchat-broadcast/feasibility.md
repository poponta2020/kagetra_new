# オープンチャット URL 自動配信の実現可能性調査（AI なしで 99% は可能か）

**調査日:** 2026-08-06 / **対象:** 本番 `mail_messages` 286件（2026-05-16 〜 2026-08-06）+ `mail_attachments` 363件
**調査方法:** 本番 DB へ SSH トンネル（読み取りのみ）。診断スクリプト = `scripts/diagnostics/openchat-coverage*.mjs`（gitignore 対象）

## 結論

**AI の有無に関わらず、「検知したら自動で LINE 配信」を 99% の正しさで回すことはできない。**
AI が足りないのではなく、**メール中に情報が存在しない**ケースと、**どの大会・どの級のグループに流すかの判断**が機械的に決まらないケースが構造的に残るため。

ユーザー案の第2案（**UI からボタン押下 → 抽出 → 確認 → 配信**）が正しい設計。既存の
`MailProcessForm`（管理者がメールを大会に紐付ける画面）が、判断が必要な情報を人間が既に
与えている唯一の地点で、そこに抽出ボタンを足すのが最も安く確実。

## 1. 母数の取り方（ここを間違えると 100% に見える）

「URL を正規表現で拾えた / 拾えた」で測ると 100% になる。正しい母数は
**「オープンチャットの招待が届いたメール」全体**。

| 区分 | 件数 |
|---|---|
| 「オープンチャット」に言及するメール（本文 or 添付テキスト） | **27** |
| うち、招待そのもの（URL または QR）を実際に運んでいる | **20** |
| うち、既存の抽出テキストから URL を機械的に取れる | **14** |
| └ `line.me/ti/g2/...` 直リンク | 11 |
| └ 短縮 URL（`x.gd` / `ourl.jp`） | 3 |
| **QR コード画像のみ（テキストに URL 無し）** | **6** |
| 言及だけで招待は含まない（「当日オプチャで連絡します」等） | 7 |

**テキスト抽出のみの上限 = 14/20 = 70%。** 99% には届かない。

## 2. 70% に届かない内訳（実データ）

### 2-1. QR コードのみ（6件・30%）— テキストには URL が一切ない
- `image/jpeg` 添付そのものが QR（例: mail#6 椿杯、#13 椿杯D級）
- **PDF のページ内に QR が画像として埋め込まれている**（例: #134/#136 京都大会「下記QRコードから」、
  #176 高校選手権「右QRコードより参加可能」、#262 中学生選手権「別紙のQRコードから」）
- PDF のテキスト層には「QR コードから参加してください」という**文章だけ**が残り、URL は無い

→ 解くには QR デコードが必要。**幸い本番には `pdftoppm`（poppler-utils）と `libreoffice` が既に入っている**
（`apps/web/src/lib/attachment-image-render.ts`）ので、PDF/Word → JPEG 化の経路は再利用できる。
不足しているのは QR デコーダ（`jsQR` 等の純 JS / wasm ライブラリ）のみ。ただし
**印刷用 PDF の QR は解像度・傾き・装飾で読めないことがあり、これ自体が新たな失敗率を持つ**。

### 2-2. メールに URL が存在しないケース（原理的に不可能）
- mail#256（協会30周年記念大会・**当会が実際に出場**）: PDF に書いてあるのは
  「オープンチャットのリンク URL は大会用 LINE アカウント内でご案内をしております」。
  つまり **LINE 公式アカウントに友だち追加してメニューを叩かないと URL が得られない**。
  どんな抽出技術でも取れない。
- mail#176 高校選手権: 「詳細は18日の監督会議にてお知らせします」

### 2-3. 短縮 URL（3件）— 取れるが「オープンチャットかどうか」が URL からは判らない
- `https://x.gd/aB3xQ`（東京東会）、`https://ourl.jp/Zx1Aq`（中学生選手権）
- ドメインだけでは openchat と断定できず、周辺テキストのラベル依存。展開して確認しない限り不確実
- 展開＝外部 HTTP アクセスが必要（新たな依存・失敗要因）

### 2-4. 本文中の URL が改行で割れる
実例 mail#208（さがみ野A級）:
```
https://line.me/ti/g2/SampleTokenFfGgHhIiJjKkLlMmNnOoPp?utm_source=invi
tation&utm_medium=link_copy&utm_campaign=default
```
今回はトークン本体は無傷だったが、**折り返し位置が数文字ずれればトークンが割れる**。
壊れた URL を配信すると「タップしても入れない」＝ 50 名に無効リンクを配る事故になる。

## 3. 抽出できても「正しく配信」できない — ここが 99% を殺す本丸

### 3-1. 1メール = 複数 URL が普通にある（14件中 4件）
| メール | URL の数 | 分かれ方 |
|---|---|---|
| #129 杉並大会 | 2 | **開催日別**（6/20土 / 6/21日） |
| #137 東京東会 | 3 | **級別**（D級 / C級 / B級） |
| #260 中学生選手権 | 5 | **部門別**（団体戦 / 1年 / 2年 / 3年 / 選抜） |

正規表現は URL のリストは出せるが、**どれを当会の誰に配るかは決められない**。
級を取り違えると、約50名に別の級のオープンチャットを配ることになる。

### 3-2. 大半は当会と無関係のメール（配信すると全部スパム）
メールは全日本かるた協会の大会 ML 経由で、**全国の大会が無差別に届く**。

- 全 286件のうち、当会イベントに紐付いているのは **21件（7%）**
- オープンチャット言及 27件のうち、当会イベント紐付けは **5件のみ**
  （#127 宮崎ABC / #137 東会BC / #208 さがみ野A / #217 鳳玉CD / #256 協会30周年）

「検知したら自動で流す」を素直に実装すると、**出場しない大会のオープンチャットを 22件配信する**。
どの大会に出るか＝人間（管理者）が `MailProcessForm` でメールをイベントに紐付ける操作でしか決まらない。

### 3-3. 当会が実際に関係する 5件だけで測り直すと
| メール | 抽出可否 |
|---|---|
| #127 宮崎ABC | ✅ 直リンク1本 |
| #208 さがみ野A | ✅ 直リンク1本（改行あり） |
| #217 鳳玉CD | ✅ 直リンク1本 |
| #137 東会BC | ⚠️ 短縮URL×3、**級別の振り分けが必要** |
| #256 協会30周年 | ❌ **URL がメールに存在しない**（LINE公式アカウント内） |

**3/5 = 60%。** サンプルは小さいが、99% でないことは明確。

## 4. パスワード（参加コード）について

- 現行コーパス（286件）で、オープンチャット言及メール中の「パスワード / 合言葉 / 暗証」出現は **0件**
- 全メールでは16件ヒットするが、いずれも Zip や名簿の文脈で、オープンチャット参加コードではない
- → **パスワード付きオープンチャットの実例は当会には1件も届いていない**。
  Flex にパスワード欄を載せる要件は「将来届いたときに手入力で載せられる」形にするのが妥当で、
  自動抽出を作り込む根拠は現時点でない（要ヒアリング）

## 5. 推奨する形

1. **トリガーは自動検知ではなく人間**（既存 `MailProcessForm` の大会紐付け操作に「オープンチャット抽出」ボタンを追加）
   - 3-2 の「当会と無関係が93%」問題が、追加コストゼロで消える
2. **抽出は決定的（AI なし）で十分** — 段階的に
   - Tier 1: 本文・添付テキストの `line.me/ti/g2/...` 正規表現（改行結合の正規化込み）
   - Tier 2: 短縮 URL（`x.gd` / `ourl.jp` / `lin.ee`）を周辺ラベル付きで候補に出す
   - Tier 3（任意）: 画像添付・PDF ページの QR デコード（`pdftoppm` は既にある。QR ライブラリのみ追加）
3. **候補を UI に並べて管理者が選ぶ**（複数 URL・級別の振り分けはここで人間が確定）
   - ここが 99% を 100% にする唯一の場所
4. **確定した URL をイベントに保存 → Flex Message で LINE 配信**
   - Flex のカードタップ = openchat 参加画面（`uri` アクション）
   - パスワードは保存欄を用意し、値があればカードに表示

AI（Claude API）を足しても 2-2（URL が存在しない）と 3-2（出場するか否か）は解けないため、
**この機能に AI を入れる価値は薄い**。
