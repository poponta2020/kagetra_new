## 意図と、採用／不採用の理由

### 抽出候補シート

- **候補行は既定で折りたたみ（採用）。** 1候補に URL・出典・級・開催日・ラベル・パスワードの6項目があり、
  全展開を既定にすると 375px で5件が3画面を超える。推定が当たっていれば**一度も開かずに配信できる**形を優先した。
  展開して初めて編集欄が出る
- **自動ラベルは medium・fg-2、手入力ラベルは bold・fg。** どちらが人の意思で決まった値かを字面で区別する。
  「推定のまま通した」と「人が確かめた」を色や印ではなく文字の太さで表す
- **「未検証」に警告色を使わない（不採用: 朱バッジ）。** 破線の下線＋fg-3 のみ。短縮 URL は危険ではなく
  確度が違うだけで、朱にすると「エラー」に読める。この画面で朱を使うのはラベル重複エラーだけに限定する
- **出典バッジは QR だけ塗り（藍）、本文・添付は輪郭のみ、手入力は砂の塗り。**
  QR は「テキストに URL が無く、目視では見つけにくかった1件」なのでそこだけ視線を集める
- **シート下端の CTA は固定フッター。** 候補が5件並んでもスクロールで CTA を見失わない
- **CTA の文言は結果と一致させる。** LINE 未紐付けでは「保存して配信（N件）」→「保存する（N件）」＋
  フッター「配信は行いません」。押してから「送られなかった」と気づく状態を作らない
- **空状態でも手入力の行が最初から1つ開いて出る。** ここが「メールに URL が無い大会」の唯一の入口になるため、
  「＋ 手入力で追加」を探させない

### LINE Flex バブル

- **バブル内のテキストは2行だけ（ラウンド2で確定）。** 「大会オープンチャット」（小・グレー）＋大会名。
  当初あった説明文（当日の対戦組合せ…）と注意書き（タップすると…）は**ユーザー判断で全削除**。
  ボタンを見れば用途は自明で、文が増えるほどボタンが下へ押し出される
- **ボタンは縦一列（不採用: carousel）。** carousel はスワイプしない人が他の級・他の部に気づかない。
  5件でもバブル1つに収まる
- **パスワードはボタン直下にモノスペースで置く。** LINE Flex に**クリップボードアクションは存在しない**ため
  「コピー」ボタンは作れない。長押しでコピーできるテキストとして置くのが上限で、
  参加画面での手入力が前提になる（この制約は仕様であって実装の手抜きではない）
- **altText はバブルとは別に必要（LINE 必須項目）。** 「オープンチャットのご案内／<大会名>」。
  バブル本体は通知に出ないため、大会名を altText 側にも持たせる。
  ※ユーザーの「テキストは上の2つだけ」はバブル内の話で、altText はこれに含まれない

### 大会詳細の欄

- **配信済み Flex と同じラベル・同じ並び。** LINE を見逃した会員が、記憶と同じ順序で辿れる
- **開催日で絞らない。** 6/21 の詳細でも 6/20 対象の行を出す。日付はラベルに出るので取り違えは起きず、
  「別の日のが見つからない」事故を防ぐ方を優先した
- **1件も無いときは見出しごと出さない（不採用: 「未設定」表示）。** 「未設定」は会員に
  「運営が忘れている」と読ませるが、実際は主催者がまだ配っていないだけのことが多い

### 配信まわりの状態

- **再配信ダイアログは全件を列挙し、今回増えた行に「（今回追加）」を付ける。**
  差分ではなく全件を送るので、何が送られるかを一覧で見せる
- **保存と配信は別々に扱う。** 配信失敗時は「N件を保存しました。配信は失敗しました」と分けて出し、
  「配信をやり直す」だけを出す。**抽出のやり直しという徒労をさせない**

## Flex はトークンの外 ★実装時の注意

LINE の Flex Message は**LINE アプリ側のレンダラ**で描画され、こちらの CSS も `--kg-*` トークンも一切届かない
（色は Flex JSON にリテラルで書く）。モックでは LINE 名前空間の値だけを `_oc.css` の `--oc-flex-*` /
`--oc-line-*` に隔離して宣言している。実装では既存 `line-flex-attachment.ts` と同様に Flex JSON 内の
リテラルになる。

| モック変数 | 値 | 用途 |
|---|---|---|
| `--oc-flex-btn` | `#2B4E8C` | ボタン背景（`--kg-brand` と同値だが別物として持つ） |
| `--oc-flex-btn-fg` | `#FFFFFF` | ボタン文字 |
| `--oc-flex-fg` | `#111111` | 大会名 |
| `--oc-flex-fg-2` | `#6E7B8A` | 「大会オープンチャット」・パスワード文字 |
| `--oc-flex-sep` | `#E7EBF0` | 区切り線 |
| `--oc-flex-pw-bg` | `#F4F6F9` | パスワード行の背景 |

`--oc-line-talk-bg` はトーク画面の再現用でありメッセージには含まれない（実装不要）。

## 忠実度チェックリスト

実装後に1項目ずつ照合する。根拠は各 `design-mock/*.html`。

- [ ] 候補行の既定は**折りたたみ**で、要約は上から「ラベル → URL」の2行（`sheet-normal.html` ②）
- [ ] 自動生成ラベルは手入力ラベルより**細く・淡い**（`.oclabel.auto` = medium/fg-2、手入力 = bold/fg）
- [ ] 「未検証」は**朱を使わず**破線の下線のみ。朱を使うのはラベル重複エラーだけ
- [ ] 出典バッジは QR だけ塗り（`--kg-brand-bg`）、本文・添付は輪郭のみ、手入力は `--kg-surface-alt`
- [ ] シートの CTA は**下端に固定**され、候補5件でもスクロールせず見える（`sheet-hard.html` Ａ）
- [ ] LINE 未紐付け時、CTA が「保存する（N件）」になりフッターが「配信は行いません」になる（`states.html` Ｂ）
- [ ] 候補ゼロのとき、手入力の行が**最初から1つ展開された状態**で出る（`sheet-hard.html` Ｃ）
- [ ] Flex バブル内のテキストは**「大会オープンチャット」と大会名の2つだけ**。説明文・注意書きを足さない
- [ ] Flex のボタンは**縦一列**（carousel にしない）。5件でも1バブル
- [ ] パスワードは対象ボタンの**直下**に、背景 `#F4F6F9`・モノスペースで出る。無い行には出さない
- [ ] `altText` は `オープンチャットのご案内／<大会名>`
- [ ] 大会詳細の欄は**開催日で絞らず全行**を出す（`event-detail.html` Ｂ）
- [ ] 大会詳細で0件のときは**見出しごと出ない**（`event-detail.html` Ｃ）
- [ ] 375px で URL が1行省略（`text-overflow: ellipsis`）され、横スクロールが出ない

## 要件への宿題（→ /define-feature openchat-broadcast）

1. **★ラベル重複の禁止ルール** — 級でも開催日でもない分かれ方では自動ラベルが全行同一になり、
   同じ名前のボタンが5個並ぶ Flex が配信される。モックは保存をブロックしているが requirements §3.2.1／AC に無い
2. **大会詳細で保存済み0件のときの扱い** — モックは「欄ごと出さない」。要件に規定が無い
3. **再配信ダイアログの「（今回追加）」印** — 要件は「全件を送る」としか書いておらず差分の可視化が規定外
4. **Flex バブルの構成** — 説明文・注意書きを置かないことを requirements §3.2.5 に明記する
