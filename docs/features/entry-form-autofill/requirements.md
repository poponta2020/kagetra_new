# entry-form-autofill 要件定義書

大会申込書（xlsx）の自動記入と Yahoo メール下書きの自動作成。

## 1. 概要

### 目的
管理者が大会申込を行う際の手作業（申込書 xlsx への会員情報の転記＋申込メールの作成）を自動化する。管理者は「申込書を作成」ボタン→プレビュー確認→確定の3ステップで、記入済み申込書が添付された送信可能な下書きを Yahoo メールに得る。

### 背景・動機
- 大会申込は「案内メール添付の申込書 xlsx に参加希望会員の情報を記入し、主催者へメール送信する」定型作業。毎回 10〜30 分の転記・整形作業が発生している
- 記入内容（姓名・ふりがな・段位・級・出場回数）はすべてシステム内に存在するか算出可能
- 送信済みメール実例の調査により、件名・本文が高度に定型化されていることを確認済み

### 大原則: 送信は構造的に不可能にする
下書き作成は **IMAP APPEND で Yahoo の `Draft` フォルダにメッセージを直接作成する**方式とする。SMTP・送信 API を一切使わないため、**このシステムからメールが送信されることはアーキテクチャレベルであり得ない**。送信は管理者が Yahoo メール（Web/アプリ）で下書きを確認して手動で行う。

## 2. ユーザーストーリー

- **対象ユーザー**: 管理者・副管理者（申込実務の担当者）
- **目的**: 参加希望が出そろった大会について、申込書の記入とメール準備を数クリックで終わらせたい
- **利用シナリオ**:
  1. 会内締切が過ぎ、参加希望（attend=true）が確定する
  2. イベント詳細の進行管理から「申込書を作成」を押す
  3. プレビューで対象会員・記入内容・宛先・件名・本文を確認（必要なら修正）
  4. 確定すると Yahoo メールに下書きが作成される
  5. Yahoo メール側で下書きを最終確認し、手動送信する
  6. 従来どおり「申込済にする」を手動で押す（本機能は状態を変えない）

## 3. 機能要件

### 3.2 ビジネスルール

#### 3.2.1 単位と対象会員
- 実行単位は**申込グループ**（entry_groups。同メール×同締切）。1 グループ = 1 申込書 = 1 下書き
- 対象会員の初期値は**グループ内全イベントの event_attendances.attend=true の和集合**（会員単位で重複排除）
- プレビューで行の追加（会員一覧から選択）・除外・全セル編集が可能
- 参加級の初期値は本人の users.grade。**自由編集可**（F級など大会独自級・当日昇級対応）
- grade が NULL の会員は警告表示（記入は空欄のまま作成可能だが警告は出す）

#### 3.2.2 テンプレート xlsx の入手
- グループに紐付く取込メール（tournament_draft 経由）の xlsx 添付を**自動候補**として提示し、プレビューで選択する
- 添付が無い／別入手の場合に備え**手動アップロード**も常に可能
- 対応形式は **xlsx のみ**（Word/PDF は Non-goal）

#### 3.2.3 セル対応付け（どのセルに何を書くか）
- 第一段: **コードのヒューリスティック**でヘッダ行を探索（「参加級」「段位」「姓」「名」「ふりがな」「氏名」「出場回数」「備考」等のキーワード）し、列対応・記入開始行を推定する
- 第二段: 推定失敗・低信頼のときのみ **Claude Haiku 4.5** にシート内容を渡してセルマップ JSON を得る
- どちらの結果も**プレビューで必ず目視確認**（マッピング結果を列見出しに表示し、手動修正可能）
- 姓名分離型（姓/名 別列）・氏名結合型の両方に対応。ふりがな同様
- **級別複数シート型（鳳玉型）**: シート名・入力規則から対象級を判定し、各会員を該当シートへ自動振分。全シートをプレビュー確認できる
- マップできない列（学校名・学年など特殊列）は**空欄のまま**とし、プレビューで手入力できれば足りる

#### 3.2.4 記入値の整形
- **段位**: users.dan から、テンプレの入力規則（ドロップダウンリスト）の選択肢形式に合わせて整形（「3段」「三」等）。リストが無ければ「N段」形式。dan が NULL/0 は「無段」（プレビューで編集可）
- **出場回数**: テンプレに出場回数列がある場合のみ、既存 appearance-counts ロジック（基準日=作成日）で自動計算しプレフィル。**編集可**（名簿未取込による過少の可能性があるため）
- **数式セルには書き込まない**（級別人数・参加費集計は COUNTIF/SUM が既にあるため触らない）
- 元テンプレの結合セル・数式・入力規則・書式を**保持**する（exceljs のラウンドトリップで実証済み）

#### 3.2.5 姓名・ふりがなのデータギャップ補完
- users.familyName/givenName/familyKana/givenKana が NULL の会員は警告表示
- プレビューでその場入力でき、入力値は **users へ書き戻す**（次回から自動で埋まる）
- 書き戻すのは**姓名・かなの4フィールドのみ**（段位・級・出場回数の編集はその場限り）

#### 3.2.6 メール下書きの生成
- **宛先（To）のプレフィル優先順**: ①テンプレ xlsx 内の「申込先」メールアドレス（正規表現抽出）→ ② AI 抽出（案内メール本文から）→ ③ 案内メールの差出人（From/Reply-To）→ ④ 空欄（手入力）
- **件名**: 主催者指定（「件名を『（所属会名）○○大会申込み』としてください」等）が案内メール本文・xlsx 内にあれば **AI 抽出でプレフィル**。指定が無ければ定型「<大会名>申込み（北海道大学かるた会）」
- **添付ファイル名**: 主催者指定があれば従う（AI 抽出）。無ければ元テンプレ名に「【北海道大学かるた会】」プレフィックスを付与（既にあればそのまま）
- **本文**: 送信済み実例の定型をコード生成。宛名（主催者名＋ご担当者様）＋挨拶＋「弊会所属N名（A級x名、B級y名…）分の参加申込書を添付ファイルにてお送りいたします」＋結び＋署名（責任者姓）。級別人数は対象会員から自動集計
- 宛先・件名・ファイル名・本文は**すべてプレビューで編集可能**。AI 抽出結果は必ず目視確認を通る
- **From**: 会定数の連絡先 E-Mail（= Yahoo アカウント）

#### 3.2.7 下書き作成の実行
- プレビュー確定 → Server Action で同期実行（数秒）: exceljs で xlsx 記入 → MIME メッセージ組立 → **IMAP APPEND で `Draft` フォルダへ**（\Draft フラグ付き）
- 成功時: 完了表示＋「Yahoo メールの下書きを開いて確認・送信してください」の案内
- **履歴（生成 xlsx・編集値を含む）は IMAP APPEND の実行前に保存する** — 失敗してもプレビューで編集した値と生成済み xlsx が失われない
- **IMAP 失敗時**: エラー表示＋**生成済み xlsx をその場でダウンロード可能**（成果物を失わない）＋再試行可能
- 再作成は何度でも可能（新しい下書きが追加される）。**旧下書きの自動削除はしない**（プレビューに「以前の下書きは Yahoo メール側で削除してください」と注意書き）

#### 3.2.8 履歴
- 作成のたびに履歴を記録: 日時・作成者・グループ・宛先・件名・ファイル名・生成 xlsx のコピー
- S1（進行管理）から最終作成日時の確認と xlsx 再ダウンロードができる

#### 3.2.9 会の定数（settings）
- key-value の settings テーブルを新設し、S3 で編集: 都道府県／所属会名／申込責任者氏名／連絡先電話／連絡先 E-Mail／振込名義人
- 申込書ヘッダ部（都道府県・所属会名・責任者・電話・E-Mail・振込名義人の行）にも同じ値を記入する（テンプレにヘッダ欄がある場合）
- 責任者交代はこの画面の編集のみで完結（コード変更・デプロイ不要）

#### 3.2.10 状態遷移との関係
- 本機能は **events.entryStatus を変更しない**。「申込済にする」は従来どおり管理者が送信後に手動で押す

#### エラーケース・境界条件
- 対象会員 0 名: 作成ボタンは押せるがプレビューで警告（空の申込書は作れない。行を手動追加すれば作成可）
- テンプレ候補 0 件: アップロード誘導を表示
- xlsx が壊れている／シートが読めない: エラー表示して中断
- AI 呼び出し失敗（API エラー）: フォールバックせず「自動推定できませんでした」としてプレビューの手動マッピングへ誘導（作成フロー自体は続行可能）
- 出場回数の算出が incomplete（名簿データ欠落）: 値は出すが警告アイコン表示

## 5. Non-goals

- **メールの自動送信（永久にやらない）** — 送信は常に管理者が Yahoo メール側で手動
- 他会分の代理申込（わすらもち会例のような別会名義の申込書作成）
- Google フォーム申込の大会への対応
- 団体戦の申込書
- Word (.doc/.docx)・PDF 記入式の申込書への対応
- 特殊列（学校名・学年・登録会など）の自動記入（空欄＋プレビュー手入力で足りる）
- 旧下書きの自動削除・Yahoo 側で編集された下書きの追跡
- entryStatus の自動遷移（「申込済にする」との連動）
- 一般会員への公開（管理者・副管理者専用）

## 6. 技術的制約・契約

- **送信機構を持たない**: SMTP クライアント・送信系 API の依存追加を禁止。Yahoo への書き込みは IMAP APPEND（Draft フォルダ）のみ
- **xlsx 操作は exceljs**（mail-worker で採用済み・ラウンドトリップ検証済み）。テンプレの数式・結合セル・入力規則・書式を破壊しないこと
- **IMAP は imapflow**（mail-worker で採用済み）。既存の YAHOO_IMAP_* 資格情報を再利用し、**web ランタイム（Server Action）から接続できるよう env を追加する**（本番 compose の web サービスへの環境変数追加が必要 = デプロイ考慮事項）
- **AI は Claude Haiku 4.5・既存 ANTHROPIC_API_KEY**。用途は (a) セルマップ推定のフォールバック (b) 指定件名・ファイル名・申込先の抽出、の2つのみ。AI 出力は必ずプレビューの目視確認を通す
- **users への書き戻しは familyName/givenName/familyKana/givenKana の4フィールドのみ**。name（合成表示名・UNIQUE キー）は変更しない
- **既存挙動の互換**: events.entryStatus・event_attendances・進行管理セクションの既存操作・mail-worker のパイプラインを変更しない
- **権限**: 管理者・副管理者のみ（settings 編集・プレビュー・下書き作成すべて。Server Action 側でも認可）
- settings テーブルは汎用 key-value として新設（将来の会定数追加に開放）
- 生成 xlsx コピーの保存方式（DB bytea / ファイル）は技術計画で確定
- **未解決の技術論点（技術計画へ申し送り）**:
  - プレビュー画面の URL 設計・グループ ID の受け渡し
  - セルマップのデータ構造（ヒューリスティック／AI／手動修正の共通表現）
  - 履歴テーブルのスキーマと xlsx コピーの保存方式
  - IMAP APPEND の MIME 組立（添付エンコード・日本語ヘッダ）の実装詳細
  - Haiku へ渡すシート表現（テキスト化フォーマット）とプロンプト設計

## 7. 設計判断の根拠

- **IMAP APPEND 方式**: 「絶対に送信しない」を運用ルールでなく構造で保証するため。Draft フォルダの存在と APPEND 可否は実アカウントで確認済み
- **exceljs 純コード記入**: openpyxl は calcChain 等の part 欠落があり不採用。exceljs は実テンプレ10件で結合セル・数式・入力規則の無傷を実証済み。AI に xlsx を直接生成させない（構造破壊リスク・コスト）
- **AI はフォールバック＋抽出のみ**: 実テンプレは4系統に収まりヒューリスティックで大半を賄える。AI 依存を最小化しコストをほぼゼロに保つ（呼び出し時も Haiku で数円）
- **プレビュー必須通過**: 名簿ミスがそのまま主催者に届く事故を防ぐ。AI 出力の目視確認ポイントを兼ねる
- **姓名かなの書き戻し**: データギャップ（既存会員 ~100 名が NULL）を運用の中で自然に解消させる（一度直せば済む）
- **グループ単位**: 申込書は1大会分（複数級・複数日を1ファイル）で送る運用実態に一致（送信済みメール実例で確認）
- **会定数を DB 化**: 学生会のため責任者交代が定期的に発生する。コード変更なしで対応可能にする

## デザインへの宿題（→ /design-screen entry-form-autofill）

対象画面は S1（進行管理へのボタン追加=変更・delta）/ S2（プレビュー画面=新規）/ S3（申込書設定=新規・単純フォーム）。中心は S2。

1. **S2 の情報設計**: テンプレ選択 → マッピング確認 → 対象会員テーブル → メール欄 → 作成ボタン、の多段情報をモバイル（375px）でどう分割するか（1画面スクロール vs ステップウィザード）
2. **編集テーブルのモバイル表現**: 列が多い（級・段位・姓・名・ふりがな・出場回数・備考）。横スクロールテーブルか、行タップ→編集シートか
3. **警告の見せ方**: 姓名かな欠損（補完入力導線つき）・grade NULL・出場回数 incomplete の3種の警告表示
4. **鳳玉型の複数シート**: シート（級）切替の UI
5. **セルマップの目視確認・手動修正 UI**: どの列→どの項目、の割当表示と修正操作
6. **メール欄**: 宛先・件名・ファイル名・本文の編集 UI（AI 抽出プレフィルの明示を含む）
7. **S1 のボタン・履歴表示**: 進行管理セクション内の配置（最終作成日時＋xlsx 再ダウンロード導線）
8. **完了／IMAP 失敗の状態表示**: 成功案内（Yahoo で確認・送信してね）と失敗時のリカバリ（xlsx DL＋再試行）
