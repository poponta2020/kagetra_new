# 添付ビューアの「開く・保存」導線 デザイン仕様（design-spec）

> `/design-screen` が出力する確定仕様。**レイアウトの詳細は `design-mock/` の HTML が正。** このファイルは HTML から読み取れない「意図・判断・データ要件・宿題」と、実装の完了ゲートである忠実度チェックリストを記述する。
> ロジック（種別判定・共有のフォールバック順・権限）は `requirements.md` が正典。ここでは再記述しない。

## 1. 対象と狙い
- **対象画面:** `/mail/attachments/[id]`（会員）・`/admin/mail-inbox/attachments/[id]`（管理者）・`/roster-files/[id]`（名簿）。3画面は意図的な独立コピーで、表示の振り分けだけを `@/lib/attachment-preview` が共有している。
- **現状の不満:** ①最多の添付である Excel がページ画像に変換されて実用にならない ②ヘッダの「元ファイル」下線リンクが iPhone の PWA では詰み（同一 WebView が QuickLook へ遷移して戻れない）で、端末にファイルを渡す手段が事実上ない。
- **狙い:** ファイルを **OS 側（Excel アプリ・ファイルアプリ）へ渡せる**ことを、どの画面からでも1タップで示す。
- **主ユーザー / 主な使い方:** ログイン済み全会員。iPhone ホーム画面アプリ・Android が主、PC も使う。

## 2. 採用した方向性
- **方向性: 案A（ヘッダにラベル付きの塗りボタン）。** ✕・ファイル名の右に `⤴ 開く・保存` を置く。sticky ヘッダなので、ページ画像が何十枚並んでも常に届く。
- **不採用案と理由:** **案B（共有アイコンのみの丸ボタン）** — ファイル名を約 50px 長く出せる利点はあるが、PDF・画像・テキストではカードが無く画面上のどこにも「開く・保存」の文字が出ない。共有アイコンは iOS では通りが良い一方 Android／PC では意味が弱く、初見の発見性が案A に劣る。ファイル名は元から truncate 前提なので、失うものが小さいと判断した。
- **視覚の正:** `design-mock/`
  - `viewer.html` — ①Excel（表計算カード）②PDF・Word・PowerPoint（プレビュー維持）③zip・変換失敗
  - `states.html` — ④ボタンの4状態 ⑤名簿ファイルビューア
  - `_aod.css` — モック固有スタイル（色・寸法は `docs/design/colors_and_type.css` の `--kg-*` からのみ取得）
  - `_preview.html` — 上記2枚と CSS を1ファイルに束ねた閲覧用（**生成物**。mock を直したら再生成する）
- **最終確認時の状態:** 1200px 幅で全5フレーム、および 375px 実寸のスマホ表示。

## 3. 視覚の正に現れない設計判断
- **Excel でヘッダとカードの導線が2つになるのは意図的。** ヘッダは「長い画面でも常に届く」役、カードは「この画面で何をすればいいか」を言う役。カード側だけにすると PDF に導線が無くなり、ヘッダ側だけにすると Excel を開いた人が「壊れている」と受け取る。
- **カードの見出しを「プレビューできません」にしない。** Excel は*できない*のではなく*しない*（表計算のページ画像は列切れ・ページ分割で実用にならない）。`Excel ファイルです` → 何をすればいいか、の順で書く。zip・変換失敗のときだけ「表示できない形式です」と事実を言う。
- **現行の但し書き「iPhone のアプリ内からは元ファイルを開けないことがあります。必要な場合は PC からダウンロードしてください。」は3画面から削除する。** この機能がその制約そのものを解消するため、残すと嘘の案内になる。
- **名簿ビューアだけボタンをタイトル直下に置く。** この画面は sticky ヘッダ（✕・ファイル名）を持たずタイトルブロックが上にあるため、ヘッダ相当の位置＝タイトル直下がスクロールせず必ず見える場所になる。名簿は実データ上ほぼ Excel なので、この画面は事実上いつもこの姿になる。
- **「もう一度タップ」は警告色（山吹 = warn）で、失敗（danger）と区別する。** 取り込みは成功していて残りは1タップ、という状態を「エラー」の赤で塗ると不必要に不安を与える。

## 4. 使用コンポーネント
- **既存プリミティブ:** `Btn`（`kind="primary"`・`size="sm"` がヘッダ／`size="md"` 相当がカード内）、`Card`（名簿ビューア）、既存の sticky ヘッダ構造。
- **新規:** 「開く・保存」ボタン（**クライアントコンポーネント**。3画面で共有する唯一の新規 UI 部品）と、表計算/プレビュー不可カード。
- **モックと実スタックの対応:**

| モックのブロック | 実コード |
|---|---|
| `.vbar` | 各ビューアの `sticky top-0 …` ヘッダ（会員は 34px/text-xs、管理者は 40px/text-sm の既存寸法を維持） |
| `.vbtn` | ヘッダ内の新規ボタン。`Btn kind="primary" size="sm"` ＋ `shrink-0` |
| `.sheetcard` | 表計算カード／プレビュー不可カード（会員は素の div、名簿は `Card`） |
| `.sc-btn` / `.rbtn` | カード内・名簿タイトル直下のボタン。`Btn kind="primary" size="md" block` |
| `.vpages` / `.vpage` | 既存のページ画像 `<img>` 縦積み（**変更しない**） |
| `.ico` の SVG | 共有アイコン（上向き矢印＋箱）。絵文字ではなく inline SVG で `currentColor` |

## 5. 状態（state）
- **通常:** `⤴ 開く・保存`（brand 塗り）。
- **準備中:** `準備中…` ／ `neutral-bg` ＋ `disabled`。アイコンは出さない（動かないアイコンは待ちに見えない）。
- **もう一度タップ:** `⤴ もう一度タップして開く` ／ `warn-bg` + `warn-fg`。取り込み済みなので次のタップは待ち時間ゼロ。
- **失敗:** ボタンは通常のまま、**下に `danger-fg` の1行**「ファイルを取り込めませんでした。通信状況を確認して、もう一度お試しください。」
- **キャンセル（共有シートを閉じただけ）:** **何も表示しない**。通常状態へ戻すだけ。
- **共有もダウンロードも不可:** ボタンは通常のまま、下に `ink-meta` の1行「この端末では共有・保存を実行できませんでした。」（責める文言にしない）。
- **失敗・不可のいずれでも、下にバイナリ route への素のリンク「元ファイルを直接開く」を出す。** 3ビューアから「元ファイル」リンクを撤去したぶん、これが原本へ到達する最後の経路になる（requirements §4.4。Codex レビュー R1 の blocker 指摘で実装漏れが判明し追加）。
- **各状態の確認先:** `design-mock/states.html`（フレーム④）。

## 6. 必要データ
- **表示フィールド:** ファイル名（`mail_attachments.filename`）・種別アイコン（`pickAttachmentIcon(contentType, filename)`）・バイナリ URL。**いずれも3画面とも既にページへ渡っており、新規クエリ・新規カラムは不要。**
- **仮データのまま確定した項目:** なし（モックのファイル名・日付は表示位置を示すためのダミー。実装では既存の値をそのまま使う）。
- **集計・導出:** なし。

## 7. インタラクション / レスポンシブ
- **操作:** ボタン押下 → バイナリ取り込み → 共有シート（無ければダウンロード）。詳細な分岐は `requirements.md` §4.1。
- **モバイル:** 375px 基準。ヘッダは `[✕ 34px][ファイル名 flex-1 truncate][ボタン shrink-0]`。ファイル名は**1行 truncate**で、ボタンを絶対に押し出さない。カード内ボタンは横幅いっぱい（最大 292px）。

## 9. ガードレール準拠メモ
- 配色は 2026-08 の藤×墨トークン（`docs/design/colors_and_type.css`）のみ使用。**トークン逸脱ゼロ**（影は `--kg-shadow-sm`、角丸は `--kg-radius-lg`、`999px` の丸は既存 `rounded-full` の語彙）。実コードへのトークン追加は不要。
- 絵文字はファイル種別アイコン（`📊 📄 📦`）のみ。これは**既存ビューアの既定の語彙をそのまま踏襲**したもので、新規の装飾用途には使っていない。ボタン内は inline SVG。
- モック固有の例外 `--aod-paper-*`（ページ画像のダミー紙面）は `_aod.css` 冒頭に隔離・明記。実装には存在しない。
- ダークモードは対象外（アプリに `prefers-color-scheme` / `dark:` の使用箇所がゼロ）。

## 10. 残課題・実装への申し送り
- **`_preview.html` は生成物。** `viewer.html` / `states.html` / `_aod.css` を直したら束ね直す（この2枚の `<body>` と2つの CSS を1ファイルに inline するだけ）。実装が参照すべき正は個別ファイルのほう。
- 共有シートに渡す `File` の MIME は拡張子ベースの自前 allowlist 定数を優先する（`requirements.md` §7）。デザイン上は影響なし。
- **見た目の実機確認は出荷後**（AC-16/17/18）。デスクトップでは共有シート自体が出ないため、ここで確認できたのはボタン・カードの見え方までである。
