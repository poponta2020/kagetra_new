PR #399 の Codex レビュー R3〜R6 の修正記録（R1/R2 は impl_fix-pr399.md / impl_fix-pr399-r2.md）。

## R3（blocker1=履歴PII[受容] / should_fix4）
- 主催者指定の抽出元を「選んだ添付が付いていたメール」へ。グループに案内メールが複数紐付くと、最新メール固定では古い添付を選んでも別大会の宛先・件名指定が適用されていた
- organizerEmail は「申込先」等の語と結び付くものだけ採用（bestScore<=0 は null）。問い合わせ先や記入例まで最優先の宛先にしていた
- 級別シートの振分先を複数選択トグル化（「上級=A/B」のテンプレに対応）
- 宛先の形式検証を MIME 組立の前に（`foo` や `user@` でも APPEND は成功し、届かない下書きが正常終了に見えていた）

## R4（blocker4 / should_fix3）
- **同じ級を複数シートに割り当てると該当会員が2枚に重複記入**され、unassigned にも overflow にも出ないため無警告だった → クライアントと Server Action の両方で検証
- 自動推定が空のとき氏名の結合列しか指定できず、姓名分離型テンプレを手動設定できなかった → 未推定時は結合列と姓/名の両方を出す
- **IMAP 再試行が冪等でなく下書きが重複** → `entry_form_drafts.message_id` を持たせ、再試行は同じ行・同じ Message-ID を使い、APPEND 前に Draft を Message-ID で照合
- 入力検証エラーを imap_failed として保存し失敗画面から直せなかった → MIME 組立（＝検証）を履歴保存より前へ
- 添付候補のサーバー側サイズ上限／ステップ1へ戻ったときのプレビューを現在値に／初期0名から追加した会員の出場回数警告

## R5（blocker2 / should_fix2）
- 案内メール本文が無いと xlsx 内の主催者指定を無視していた → 本文が空でもシートのテキストを抽出対象に
- **同時再試行で下書きが重複し得た**（SEARCH→APPEND は接続をまたいで原子的でない）→ 状態遷移（pending/imap_failed → appending）を条件付き UPDATE で claim。再試行時は SEARCH 失敗を「未存在」に倒さない
- 独自級（F級）が「級未設定」として集計・表示されていた → 未設定は null/空欄だけ、独自級は表記のまま数える
- 会員編集シートが短い画面でスクロールできず保存ボタンが画面外だった → min-h-0 + overflow-y-auto

## R6（blocker4/5 修正・1件見送り）
- **クライアント由来の CellMap が未検証**で、列に `F12` を送ると `F1212` へ書き、同じ列に2項目で後勝ち上書きになり、どちらも成功として誤配置の申込書ができた → Workbook と突き合わせて生成前に検証
- 履歴を作る前の例外で失敗画面へ飛ばさない（直す導線が無い）
- **ヘッダ欄が既存値のあるセルを上書き**していた。記入先は推定で決まるのにプレビューに出ないため、誤指定でラベルを潰す経路があった → 非空セルは触らない
- `appending` のまま取り残された行を回収するリース（append_started_at）
- **見送り**: xlsx の展開爆弾対策。同じ経路は mail-worker の結果取込・名簿取込に既にあり、この PR で新設した穴ではない。隔離プロセスでの解析が要る規模なのでプロジェクト横断の課題として扱う

## 効いた設計の型
- 「null＝全件」を意味するフィールドは、複数件の文脈で未設定のまま通すと静かに全件複製になる（targetGrades）
- 外部への書き込み（IMAP APPEND）は「成功したが応答が返らない」を必ず想定する。冪等キー＋claim＋リースの3点セットが要る
- クライアントが自由入力できる構造（CellMap）は、型が通っても意味が壊れる。実データと突き合わせた実行時検証を生成の手前に置く
