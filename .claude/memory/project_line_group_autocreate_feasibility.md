2026-09-14 の調査。「match-tracker の line-chat-worker（Playwright で OAM を操作・月1回人がログインしてコードを打つ）と同じ技術で LINE グループを自動作成できないか」。**結論＝公式手段では不可能。可能性が残るのは「一般ユーザー向け公式クライアント（LINE Chrome 拡張）を Playwright で操作する」経路と非公式プロトコルの2つだけで、どちらも規約グレー＋PoC 未実施。要件定義には進めず、ユーザー判断待ち。**

## 「今の仕組み」の正体（応用元）

- match-tracker `line-chat-worker/`（同一 Oracle VM の Docker 常駐）が Playwright で `chat.line.biz`（LINE Official Account Manager）を操作し、**予約送信を登録するだけ**。ログインは storageState（cookie）を持ち回り、24h セッションはクリックスルーで自動回復、**30日 SSO は月1回人がフルログイン**（LINE account 方式＝スマホでコード確認）。
- 操作しているのは**公式アカウント（OA）の管理画面**。OA は「グループに参加」はできるが「グループを作る／人を招待する」機能が**そもそも画面に無い**ので、この技術を延長しても届かない。

## 公式手段（3系統すべて不可）

| 経路 | 結論 | 根拠 |
|---|---|---|
| Messaging API（Bot） | 不可 | グループ関連 API は概要取得・メンバー取得・退出のみ。作成・招待のエンドポイントは存在しない（developers.line.biz group-chats） |
| OAM（公式アカウント管理画面） | 不可 | 「グループトークに参加はできるが作成・招待はできない」。OAM の「グループ」機能は複数 OA を束ねる管理単位で、トークではない（lycbiz マニュアル） |
| LINE WORKS Bot API | 不可 | トークルーム作成 API はあるが Bot 入りルームに外部 LINE ユーザーを招待できない（worksmobile コミュニティ） |

## 残る2経路（どちらもグレー）

### A. LINE Chrome 拡張（公式一般クライアント）を Playwright で操作
- Chrome Web Store に現存（v3.7.2・2026-02-25 更新・LY Corporation）。機能説明にグループ作成が明記。
- Playwright は `launchPersistentContext` + `--load-extension` で MV3 拡張を載せられる（Linux は xvfb か `channel: 'chromium'`）。
- **OAM 方式との決定的な違い**: (1) 操作主体が**一般ユーザーのアカウント**（電話番号必須）。凍結時に失うのは Bot でなく人のアカウント。(2) Chrome 版は自動ログイン非対応＝ワーカーが**メール＋パスワードを保持**して毎回打つ必要がある（直近ログイン済みならスマホの認証番号は省略される）。OAM 方式は cookie だけで済んでいた。(3) グループに入れられるのは**作成アカウントの友だちだけ**。会員全員がその アカウントを友だち追加している前提。(4) UI で友だちを選ぶ手掛かりは**表示名のみ**（「みお」「じょー」等の重複・変更に弱い）。`GET /v2/bot/group/.../member/{userId}` の displayName と突合する設計が要る。
- 規約: LINE 利用規約 第15条(5)「BOT、チートツール、その他の技術的手段を利用して当社サービスを不正に操作する行為」の「不正に」がグレー。OAM 自動操作と同じ種類のグレーだが、賭けているものが人のアカウントである点が重い。
- **未確認（PoC で確かめること）**: 拡張が Playwright で実際に起動・ログインできるか／ログイン持続の実態（パスワード再入力の頻度・スマホ通知）／グループ作成 UI の自動操作可否と「友だちをグループに自動で追加」の初期値／作成時に Bot（OA）を同時にメンバーへ入れられるか／短時間に複数グループを作ったときのスパム判定。

### B. 非公式プロトコル（CHRLINE 等の Thrift クライアント）
- `createChat` / `inviteIntoChat` が存在し技術的には最短。**明確な規約違反**で、selfbot 系リポジトリは「アカウント凍結＋電話番号の永久 BAN」を警告している。プロトコル変更でライブラリが壊れる。**採用しない前提で記録**。

## 規約セーフな代替（作成は人・参加を自動化）
- 管理者がスマホでグループを作り、**招待リンク**を Bot 経由で配信して会員が自己参加する。友だち関係は不要だが**双方が年齢確認済み 18 歳以上**である必要がある。
- 現状維持（管理者が作成→Bot を招待→招待コード紐付け）。

## 採用する場合の前提条件（要件定義に持ち込む論点）
1. 作成アカウントは**会専用の一般アカウント**（専用電話番号）にする。管理者個人のアカウントを自動操作に晒さない。
2. 会員→専用アカウントの友だち追加を導入フローに組み込む（Bot 友だち追加と同じ導線）。
3. 表示名だけで人を同定しない。Messaging API の displayName と `users.line_user_id` を突合し、曖昧なら止める。
4. 先に **ローカル headed の PoC**（Chrome 拡張 + Playwright でグループ作成 1 回）で上の未確認項目を潰してから要件定義に入る。
