大会別 Bot が紐付け成立時に返す案内③を、単一の人数から**役割別の内訳**へ改訂する定義。
正典 = docs/features/event-line-broadcast/requirements.md §3.1.3 / §3.1.3a〜3.1.3c
（新スラッグは作らず、③の文面を所有する event-line-broadcast の delta として更新した）。

## 新しい③

```
@管理者
グループの人数が12名であることを確認してください。

内訳
大会参加者：9名
管理者：1名（土居）
会計：1名（酒井）
副連絡責任者：0名（遠征届不要のため）
Bot：1名
```

## ★前提の反転（最重要）

現行は**ゲストを人数に含め**「内他会〇名」を併記していた。理由は requirements に
「グループには他会の参加者も入る」と明記されていたため。**実態は逆でゲストを招待しない**
運用だったので、ゲストを人数から除外し併記も廃止する。
つまり従来の③は、実際にはグループにいない人を含めた数で照合を求めていた。

ユーザーは途中の選択肢で一度「現行どおり含める」を選んだが、原文と矛盾するので
再確認したら「ごめんやっぱゲストはいれない！！！」。**選択と原文が食い違ったら聞き直す。**

## 決めたこと

- **管理者 = `role='admin'` の1名だけ**（vice_admin は大会グループに入らない）。
  ③のメンション対象も admin+vice_admin 全員 → `role='admin'` のみへ絞る。
  ただし `loadAdminLineUserIds` / `resolveAdminMention` の意味は変えず、③専用関数を足す
- 役割行は**名字**を出す（`family_name ?? name`）。本番は全33名 family_name 済み
- **1人1バケットの排他**: 大会参加者 ＞ 会計 ＞ 副連絡責任者 ＞ 管理者。
  合計＝各行の単純和。会計は運用上 `role='vice_admin'` なので排他が無いと二重計上になる
- **Bot を内訳と合計に入れる**（`Bot：1名`）。LINE のメンバー数とそのまま比べられるように
- 副連絡責任者の分岐（上から）: ①排他で全員移動 → 移動先の注記 ②遠征届不要 →
  `0名（遠征届不要のため）` ③残り0人 → `0名（未設定）` ④ゲストあり →
  `N名（飯塚・他会参加者ありのため）` ⑤ → `N名（飯塚）`。
  **②を③より先に見る**のは、遠征届が要らない大会で「未設定です」と無用な警告を出さないため
- **ゲストは無条件で遠征届の対象**（`is_circle_member` の ON/OFF を見ない）。
  ゲストは「サークル員だが協会登録が他会」の人なので遠征届が要る
- travel-report R5 の正式な対象者判定は「サークル所属 ON ∧ 参加 ∧ 確定状況=確定」だが、
  **確定状況は紐付け時点に存在しない**（名簿確定は数週間後）ので③では参照しない

## 本番データ（2026-09-14 実測）

admin=土居1名 / vice_admin=坂本・酒井・飯塚3名（酒井が `is_treasurer`）/
`is_travel_report_submitter` **0人** / `is_circle_member` **全員 OFF** / `role='guest'` **0名**。
→ **出荷しても当面は副連絡責任者の行が常に `0名（遠征届不要のため）`**。
フラグ投入はコードでなく運用（会員編集・`/admin/members/circle`）で Non-goal。

## 技術設計の核心

`buildMentionMessage` の `MentionValue` は `number | { dateIso }` だけで自由記述を受けない
（textV2 が `{}` をプレースホルダとして解釈するため）。名字を入れるので
**`MentionValue` に `{ text: string }` を足し、差し込み時に中括弧を除去**する。
template に名字を連結する方式は不採用 — `assertNoBraces` が throw すると①〜④の reply が
丸ごと落ちる。この設計なら **template は静的リテラルのまま**（括弧の中身も `%s` で受ける）。

`countGroupEntrants` の呼び出し元は line-webhook-handler.ts の1箇所だけ＝影響範囲が閉じている。
`entry-headcount.ts` 冒頭コメントの「ゲスト: 含む」対比表は今回の変更で逆になるので要書き直し。

## レビューで潰した穴（2026-09-14・commit ce402f2）

- **「注記は付けない」の衝突**: 排他の注記（`0名（大会参加のため）` 等）は**その行が0名のときだけ**、
  副連絡責任者の分岐注記（`遠征届不要のため` / `他会参加者ありのため`）は**外れた人数に関係なく**評価。
  切り分けないと `2名（飯塚・酒井・他会参加者ありのため）` のケースで実装者が迷う
- **AC が恒真になる罠**: 「合計＝5行の和」は合計を行の和として実装すれば必ず通る＝何も検証しない。
  テスト側で独立に数えた実人数と突き合わせる条件へ書き直した。**AC を書いたら
  「その実装で必ず通ってしまわないか」を一度疑う**
- **Wave 途中で typecheck が落ちる分割**: 「DB 層で旧関数を削除」と「呼び出し元を差し替え」を
  別 Wave にすると、その間リポジトリが型を通らない。各タスクの完了条件が typecheck なら
  **削除は呼び出し元の差し替えと同じタスクに置く**
