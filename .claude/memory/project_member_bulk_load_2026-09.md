## 確定した判断（ユーザー承認済み）

1. **`popon`(admin) = 土居悠太 本人**。新規作成せず既存行を更新し `name` を `土居 悠太` へ改名。
   ★`users.name` は UNIQUE だが `popon` と `土居 悠太` は別文字列なので、**気づかず重複行を作る**のが最大のリスクだった。
2. **既存行は NULL の穴埋めのみ**（`COALESCE(col, 値)`）。「格納パスの値を正として上書き」の当初指示に対し、
   実際に突合すると**内容の衝突はゼロ**で、差分は (a) 空欄の穴埋め (b) 表記ゆれ (c) **ソースの方が情報が欠けている**
   の3種類しかなかった（坂本の "26号" 欠落・"市" 抜け、田中の "407号"）。ソースが優る箇所は飯塚の address2 1件だけで、
   そこだけ明示上書き。→ **「上書きか否か」ではなく「衝突が実在するか」を先に測ってから聞くのが正解**だった。
3. 昇段申請は**全件「新段位」**で採用。4ファイルとも「承認」欄は空欄（＝会側の控え）で承認可否は判定不能。
4. 新規26名: `role=member` / `is_invited=true`（false だと大会の出欠回答ができない）/ `zen_nichikyo=true` /
   LINE 連携なし / `email` NULL / `name` は `姓␣名`（半角スペース・招待登録フローの `${familyName} ${givenName}` と同形）。
   サークル所属・学部・学年は入れない（遠征届の残作業）。
5. 会員区分（正会員/準会員）は**保存しない**（`users` に列が無い。生年月日から導出可能）。
6. 電話はハイフン除去で統一。郵便番号は7桁数字。
7. `テスト会員` を物理削除（`users.id` を参照する **34 列すべて 0 件**を事前確認）。

## ソース側で見つかった不具合と対処

- **openpyxl の 3行ブロック解釈**: 段位申請書は1申請=3行で、`row+2` は建物名とは限らず
  **住所1の続き（丁目・番地）**が入っていることがある。3名で番地が address2 に取り残されていた。
  → 「`row+2` が数字始まりなら最初の空白までを address1 へ寄せる」で機械的に解決。
- **都道府県の二重付与**: L列の都道府県を無条件に前置すると `北海道北海道…` になる（J列に既に入っている行がある）。
  → 前方一致で判定。
- **Excel の型化け**: 郵便番号が数値になり先頭0が落ちる／住所2 `-401` が数値 `-401` になる。
- 誤記3件を修正（白石区「本道」→「本通」＝〒003-0026 の実町名／長音記号 `ー` がハイフン代わり／`-401` を住所1へ結合）。
- **行の欠番は本物**（全日協登録シートは row 2-26 と row 53 のみ）。`data_only=False` でも同じ＝
  数式キャッシュ落ちではないことを確認してから投入した。

## 手順（再現用）

スクラッチに `build.py`（xlsx→members.json）→ `report.py`（本番との突合）→ `gen_sql.py`（load.sql 生成）。
本番へは SSH + `docker exec kagetra-postgres psql` の独立系統。
**`COMMIT` を `ROLLBACK` に差し替えた空撃ちを先に流して件数を確認**してから本実行した。
事前に `pg_dump -t public.users --data-only --column-inserts` でバックアップを取得（スクラッチ）。
