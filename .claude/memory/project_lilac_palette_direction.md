# ライラック配色 + 立体感（design-spec 確定 / 実装未着手）

**日付**: 2026-08-28
**正典**: `docs/features/lilac-palette/design-spec.md`
**状態**: design-spec 確定・ユーザー承認済み・**実装未着手**

## 決まったこと

アプリ名が「ライラック」になる見込み＋現行配色が地味、という相談から、配色の全面刷新と立体感の付与を design-spec に確定させた。UI リデザインなので **design-spec が要件成果物**（define-feature は回さない）。

### 中心的な設計判断

**「ライラック」を西洋 lilac ではなく和の藤色として読む**。西洋 lilac は OKLCH 色相 326°（赤紫）で化粧品的・児童向けに寄る。和の藤色 290° / 菫色 297° / 紫苑 295° を採り、**軸を色相 295°** に置いた。`design.md` の「百人一首＝古典的だから和紙×墨」という論の**中**に収まるため、名前の駄洒落ではなく設計として説明できる。

### 「地味」の原因は測定できる（重要）

ベージュだからではない。**面と文字を作る 14 トークンの色相が全部 80–92° の 1 系統**で、かつ **カード↔背景の明度差 ΔL が 0.024**（ほぼ知覚不能）、**ピル地↔背景が 0.009**。加えて `Card` プリミティブに**影が一切ない**。この診断のおかげで、名前が「ライラック」に確定しなくても変更を単独で正当化できる。

### 採用した案

- 配色 = **案1: 藤（brand・success）＋ 朱（accent・danger、据置）＋ 琥珀（warn、新設）**
- 立体感 = **案D: 4 段の elevation ＋ 背景に微細ノイズ（SVG feTurbulence, opacity 0.05）**
- `success == brand` の同値関係は**維持**（参加＝藤色）。success だけ藍を残す案は紫と青が濁るため不採用

### 琥珀を足した理由（装飾ではない）

現行は `warn-bg`/`warn-fg` が `danger-bg`/`danger-fg` と**完全に同じ hex**。「締切まで3日」も「送信エラー」も同じ赤だった。第 3 色は**情報設計の誤りの修正**として入れる。色相 75–78° は**今回捨てる和紙ベージュ（88°）とほぼ同じ系統**で、和紙の記憶が差し色として残る。

緑は不採用（LINE 緑と衝突・success は藤が担うので役割なし）。

## 実装前に必ず読むこと

- **影の alpha は据え置けない**。canvas が L 0.953 → 0.930 と暗くなり、暗い地の上では影が暗くする余地が減る。同じ値を持ち越すと今より見えなくなる。かつ 1 層の影は「にじみ」で、2 層（接地＋環境光）にして初めて紙に見える
- **`--color-warn` の新設は `bg-warn`/`border-warn`/`text-warn` を live 化する**。裸の `warn` 参照は現時点で **0 件**（PR #532 のクリーンアップが完全だった）を確認済みだが、実装直前にもう一度 grep すること。`text-ink-1` 事案のちょうど逆パターン
- **`brand-bg` は「ブランド淡色面」と「参加ピルの地」を兼ねる**。`neutral-bg` を彩度 0.011 の無彩色寄りに落としてあるのはこれと弁別するため。片方だけ直すと両方壊れる
- `design.md` の視覚原則を **2 箇所改訂する**（「紫の会議ピルは作らない」の明確化 ＋「No decoration」にテクスチャの例外を追加）。**ユーザー承認済み**
- `docs/design/colors_and_type.css` は globals.css が `Source:` として参照する**第 2 コピー**。放置すると腐るので同時更新
- 検証は `var(--color-*)` の**参照名**で行う。**hex 照合は無効**（`success == brand`、`danger == accent` で hex が衝突しているため）
- 影とテクスチャは**純粋な描画なので jsdom で検証不能**。`/design-screen` Path L で実画面に当てるか、未確認として報告する
