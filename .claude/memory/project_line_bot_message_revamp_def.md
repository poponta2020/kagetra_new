大会別LINE Bot（プール30・申込グループ単位で紐付け）が送る全メッセージを棚卸しし、文面・宛先を全面改訂する改修。親Issue #519 / 子 #520-527。

## 棚卸しで判明した構造（次に触るとき最初に読む値）

- push/reply の実装は **6モジュールに分散**し、重依存（sharp/libreoffice）を避けるため**意図的に共通化されていない**。`grep -rn "api.line.me"` が唯一の網羅手段（名前ベースの grep では漏れる）
- `'vice_admin'` の権限判定は **43ファイル・58箇所にインライン展開**。ロールを増やすと全箇所改修になる
- 級別グループ配信は **internal_deadline（会内締切）**、ライフサイクルのリマインドは **entry_deadline（主催者締切）** を表示している。同じ大会で違う日付が並ぶ。今回は是正せず放置（ユーザー判断）
- `tallyEntryFeesForGroup` の母集団は**出欠回答「参加」ベース・ゲスト除外・延べ人数**。確定名簿ベースではないので、抽選のある大会では落選者が混ざる

## 主要な設計判断

1. **ロールを増やさず `users.is_treasurer` の boolean 1列**。権限は既存 role のままで、会計担当には vice_admin を付与して運用する。**認可判断にこの列を使わない**のが契約。理由=58箇所の判定を触らずに済む
2. **振込連絡は名簿確定後**に置いた。申込完了時点では抽選前で当選者が未確定＝金額が出せない。E-2 は「振込連絡は名簿確定時に連絡します。」の予告文に退く
3. **プレビュー必須・編集できるのは級ごとの人数だけ**（単価は協会規定額から `resolveEntryFee` が導出。管理者に上書きさせない）。全自動にしない理由は上記の母集団問題＋確定名簿が添付ゼロの本文だけで届く大会が実在するため（#509 の杉並AB）
4. **振込連絡を2通に分けたのは textV2 の制約**。中括弧をプレースホルダとして解釈するため、**メンションを含むメッセージに自由記述を混ぜられない**。1通目=メンション+数値のみ / 2通目=口座情報の自由記述。これは読みやすさの分割ではなく設計上の必然
5. **文面の正典を既存機能の requirements.md に残し**、新スラッグは索引に徹した（二重化させない）

## LINE 仕様の確定事項

- `textV2` + `substitution` + `mentionee` でメンション送信可。`type:"all"`（@All）と `type:"user"`（userId 指定）。substitution は1メッセージ最大100
- **userId はプロバイダー単位で発行**。イベント用Botチャネル30個とLINEログインチャネルは**同一プロバイダー**（ユーザー確認済み）なので `users.line_user_id` をそのまま `mentionee.userId` に使える。プロバイダーを分ける変更を将来したらこの前提が壊れる
- reply は1回5通まで・**課金通数を消費しない**。紐付け完了の①〜④は reply で送る

## 変更の骨子

- A-1（join時の案内返信）廃止。A-3（紐付け完了）を①〜④の4吹き出しへ分割（②=@All+主催者締切、③=@管理者+申込人数「〇名（内他会〇名）」、④=要綱前置き）→ ⑤以降は既存の要綱Flex
- E-1/E-2/E-3・F-1〜F-6 の文面を差し替え。**全種別から大会名と金額を全廃**、日付は曜日つきへ
- 複数日グループの日別ラベル生成は撤去。ただし **(グループ,種別,基準日) の束ね処理は維持**（3日グループで1通のまま。回帰ACとして固定）
- B（要綱カード）・C（メール配信）・D（オープンチャット）・級別グループ配信・管理者個人アラートは**一切触らない**
